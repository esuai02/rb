과정 지향 피드백은 “정답/오답을 예쁘게 말하는 UI”가 아니라, 플레이어가 **무엇을 관찰했고, 어떤 전략을 썼으며, 다음에 무엇을 바꾸면 되는지** 즉시 행동으로 연결해 주는 설계입니다. 수학마을 게임에서는 점수·등수보다 **선택 → 결과 → 원인 단서 → 수정 시도 → 변화 확인**의 짧은 루프를 화면과 월드에 구현하면 됩니다.

교육 피드백 연구에서도 효과적인 피드백은 개인을 칭찬·평가하기보다 과제·전략·자기조절에 초점을 맞추고, 학습자가 다음 행동을 할 수 있도록 구체적으로 안내해야 한다고 봅니다. 수학에서도 정답 여부만 알려주는 것보다, 목표에 도달하기 위해 사용할 전략을 보이는 과정 피드백이 동기와 참여에 도움이 될 수 있습니다. [educationendowmentfoundation.org](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/feedback)

## 피드백의 4단 구조

모든 수학 행동 뒤에 아래 4단계를 짧게 연결하세요.

```text
1. 관찰: 방금 무슨 일이 일어났는가?
2. 해석: 어떤 선택이 결과를 만들었는가?
3. 다음 행동: 무엇을 바꿔 볼 수 있는가?
4. 재시도: 바로 수정해 볼 수 있는가?
```

### 예: 일차함수·경사 미션

```text
나쁜 피드백:
“오답입니다. 정답은 기울기 2입니다.”

좋은 피드백:
“열차가 목표 승강장보다 낮게 도착했어.”
→ 화면에 실제 도착 위치와 목표 높이를 동시에 표시
“같은 거리에서 더 높이 올라가려면, 경사를 어떻게 바꿔야 할까?”
[경사 조절] [다른 경로 보기]
```

핵심은 “기울기 2”라는 답을 알려주는 대신, 플레이어가 **도착 높이와 목표 높이의 차이**를 보고 다음 선택을 하게 만드는 것입니다.

## UI가 맡을 일, 월드가 맡을 일

과정 지향 피드백은 팝업을 많이 띄울수록 나빠집니다. UI는 최소한의 해석과 다음 행동을 보여 주고, 월드는 실제 결과를 보여야 합니다.

| 피드백 요소 | 월드에서 보여 줄 것 | UI에서 보여 줄 것 |
|---|---|---|
| 선택 결과 | 열차 도착 위치, 드론 경로, 불이 켜진 신호 | 목표와 현재 결과의 짧은 비교 |
| 원인 단서 | 경사·거리·방향선, 에너지 흐름 | 한 문장짜리 질문 또는 힌트 |
| 수정 가능성 | 조절 레버, 다른 경로, 재배치 가능한 부품 | `다시 조절하기` 버튼 하나 |
| 성공 변화 | 도시 점등, 길 개방, NPC 반응 | 새 능력·다음 목표 안내 |
| 전략 기록 | 플레이어가 만든 노선/패턴의 흔적 | “이번에는 ___을 먼저 확인했어” 요약 |

### 기본 레이아웃

```text
┌────────────────────────────────────┐
│ 목표 높이 ●                         │
│ 현재 도착 ○                         │
│                                    │
│ “목표보다 1층 낮게 도착했어.”        │
│ “경사나 출발 높이를 바꿔 볼까?”      │
│                                    │
│              [경사 조절하기]        │
└────────────────────────────────────┘
```

이 카드는 화면을 가리지 않도록 하단 또는 측면에 작게 표시하고, 2~4초 뒤 자동 축소합니다. Roblox UI는 가장 관련성 높은 정보만 쉽게 찾을 수 있게 우선순위를 정해야 하며, 작은 화면에서 텍스트·컨트롤이 명확히 보이도록 설계해야 합니다. [create.roblox](https://create.roblox.com/docs/production/game-design/ui-ux-design)

## 피드백 문장 템플릿

문장은 “너” 평가가 아니라 **행동과 결과**를 주어로 씁니다.

### 피해야 할 문구

```text
틀렸어.
수학을 더 연습해야 해.
좋은 학생이야.
똑똑해!
너는 기울기를 이해하지 못했어.
레벨이 낮아서 실패했어.
```

### 권장 문구

```text
선택한 경로는 목표보다 낮게 도착했어.
출발 위치는 맞았어. 이제 변화량을 확인해 보자.
오른쪽 방향은 맞아. 앞뒤 위치를 한 번 더 비교해 보자.
이번에는 에너지를 아꼈어. 더 짧은 경로도 찾아볼 수 있어.
두 신호가 거의 동시에 켜졌어. 다음에는 타이밍을 맞춰 보자.
방금 사용한 방법은 다른 노선에서도 시험해 볼 수 있어.
```

| 상황 | UI 피드백 | 다음 행동 |
|---|---|---|
| 좌표 순서 혼동 | “가로 위치는 맞아. 세로 위치를 다시 보자.” | y방향 타일만 강조 |
| 기울기 너무 작음 | “목표보다 낮게 도착했어.” | 더 큰 상승 변화 선택 |
| 기울기 부호 혼동 | “이 구간은 내려가야 신호와 만날 수 있어.” | 하강 경로 하이라이트 |
| 출발점 혼동 | “경사는 맞아. 시작 위치가 달라졌어.” | 출발 고도 조절 |
| 비율/차이 혼동 | “양은 늘었지만, 전체와의 비율은 달라졌어.” | 비율 바·분할 블록 표시 |
| 패턴 회전 혼동 | “조각의 방향은 바뀌었어. 뒤집힌 건 아니야.” | 회전 애니메이션 재생 |
| 협동 타이밍 실패 | “두 신호가 잠깐 어긋났어.” | 3초 동기화 창 표시 |

## 피드백의 단계화

한 번에 정답과 설명을 다 주지 말고, **가장 작은 힌트부터** 제공합니다.

```text
Level 0: 결과만 보여 주기
Level 1: 목표와 현재 결과 비교
Level 2: 확인할 변수 하나 지목
Level 3: 선택 가능한 전략 두 개 제시
Level 4: 부분 해결 또는 시범 행동
```

### 경사 미션 예시

```text
첫 실패:
“열차가 목표보다 낮게 도착했어.”
→ 목표 높이와 실제 도착 높이만 표시

두 번째 유사 실패:
“출발 높이는 같아. 경사가 달라지면 도착 높이도 바뀌어.”
→ 경사 레버를 약하게 점멸

세 번째 유사 실패:
“더 높이 가려면 이 레버를 위로 움직여 보자.”
→ 조절 방향 강조

네 번째:
드론이 절반만 조절하는 시범
→ 플레이어가 마지막 조절을 완성
```

이 구조의 원칙은 “정답을 늦게 주는 것”이 아니라, **플레이어가 아직 스스로 사용할 수 있는 정보만 먼저 제공하는 것**입니다. 피드백은 학습자가 실제로 받아들이고 사용할 수 있어야 하며, 개선을 위한 시간이 제공돼야 효과가 납니다. [educationendowmentfoundation.org](https://educationendowmentfoundation.org.uk/news/eef-publishes-new-guidance-report-teacher-feedback-to-improve-pupil-learning)

## 성공할 때도 과정 피드백

과정 지향 피드백은 틀렸을 때만 쓰면 안 됩니다. 성공했을 때도 “정답!”으로 끝내지 말고, **무엇이 잘 작동했는지**를 짚어 주세요. EEF도 고품질 피드백은 오류를 지적하는 데 그치지 않고, 올바르게 수행했을 때도 제공되어야 한다고 설명합니다. [educationendowmentfoundation.org](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/feedback)

```text
나쁜 성공 피드백:
정답! +50 XP

좋은 성공 피드백:
“출발 위치와 경사를 함께 확인해서 정확히 연결했어.”
→ 게이트가 점등
→ “이 방법을 다음 노선에도 써 볼 수 있어.”
```

### 성공 피드백 예시

| 성공 행동 | 보여 줄 피드백 |
|---|---|
| 목표 위치를 한 번에 찾음 | “가로와 세로 위치를 함께 확인했어.” |
| 틀린 뒤 전략을 바꿈 | “처음 결과를 보고 경사를 조절했어.” |
| 두 경로를 비교함 | “두 경로의 에너지 사용량을 비교했어.” |
| 팀원에게 핑을 보냄 | “팀이 같은 신호를 보게 만들었어.” |
| 다른 미션에 전략을 적용 | “이전 노선의 방법을 새 길에 적용했어.” |
| 힌트 없이 완주 | “필요한 단서를 스스로 연결했어.” |

단, “너는 천재야”, “수학 천재”, “최고의 학생” 같은 사람 중심 칭찬은 피하세요. 성격·능력을 평가하는 메시지보다, **관찰 가능한 전략과 행동**을 짚는 메시지가 더 유용합니다. [educationendowmentfoundation.org](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/feedback)

## “수정 화면”을 만들지 말고, 수정 행동을 만들기

학생이 피드백을 읽고 다시 메뉴를 열어 수정하게 하면 흐름이 끊깁니다. 피드백 카드 안에는 되도록 한 개의 행동만 두세요.

```text
나쁜 흐름:
실패 팝업
→ 해설 읽기
→ 닫기
→ 메뉴
→ 다시 시작
→ 로딩
→ 재시도

좋은 흐름:
월드에서 결과 확인
→ “목표보다 낮음”
→ [경사 조절하기]
→ 레버가 바로 활성화
→ 즉시 재시도
```

### UI 버튼 규칙

- 실패 카드 버튼은 1개만
- 버튼 이름은 정답이 아니라 행동: `경사 조절하기`, `경로 비교하기`, `다시 맞추기`
- `정답 보기`는 기본 버튼이 아니라 최종 힌트 단계에서만
- “다시 하기”보다 무엇을 다시 할지 드러내기
- 재시도 시 카메라·플레이어 위치·불필요한 대화를 초기화하지 않기

## 플레이어가 스스로 말하게 만드는 UI

과정 피드백의 마지막 단계는 게임이 항상 말해 주는 것이 아니라, 플레이어가 전략을 짧게 선택·표현하게 하는 것입니다. 단, 아동·글로벌 환경에서는 자유 입력 문장을 요구하지 마세요.

### 사전정의 전략 선택

```text
“다음에는 무엇을 먼저 확인할까?”

[출발 위치]
[방향]
[변화량]
[팀 신호]
```

이 선택은 정답 평가가 아니라 다음 힌트의 우선순위를 정하는 데 씁니다.

```text
플레이어가 [방향] 선택:
→ 다음 미션에서 방향 화살표를 먼저 강조

플레이어가 [변화량] 선택:
→ 다음 미션에서 높이 차이 시각화를 먼저 제공
```

이 방식은 자기조절의 작은 형태입니다. 피드백이 과제 수행뿐 아니라 학습 관리·자기조절 전략을 지원할 수 있다는 근거와도 맞습니다. [educationendowmentfoundation.org](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/feedback)

## 협동 미션에서의 과정 피드백

협동 상황에서는 누가 틀렸는지 대신 팀의 상태와 다음 조율 행동을 보여 줘야 합니다.

```text
나쁜 피드백:
“Alex가 늦어서 실패했습니다.”

좋은 피드백:
“두 신호의 시간이 2초 차이였어.”
“다음에는 드론 도착 후 함께 켜 보자.”
[준비 신호 보내기]
```

### 협동 UI 예시

```text
┌──────────────────────────────────┐
│ 팀 신호 연결                      │
│                                  │
│ 나      ● 준비됨                  │
│ Alex    ○ 이동 중                 │
│                                  │
│ “두 불빛이 3초 안에 켜지면 연결돼.” │
│              [준비 신호 보내기]   │
└──────────────────────────────────┘
```

피드백은 팀원 평가가 아니라 다음을 보여 줍니다.

- 지금 누가 무엇을 하고 있는가
- 공동 목표까지 무엇이 남았는가
- 다음에 어떤 타이밍·역할 조정이 필요한가
- 성공하면 어떤 팀 변화가 생기는가

## 시각·청각·촉각의 다중 채널

텍스트만 쓰지 마세요. 특히 글로벌 아동 게임에서는 같은 피드백을 여러 감각 채널로 제공합니다.

| 의미 | 시각 | 소리 | 촉각/동작 |
|---|---|---|---|
| 목표에 가까워짐 | 경로 빛이 밝아짐 | 음 높이가 상승 | 드론이 부드럽게 가속 |
| 목표를 넘김 | 목표선 위로 지나감 | 짧은 상승음 뒤 완화 | 레버가 상단에서 멈춤 |
| 목표에 못 미침 | 목표선 아래 정지 | 낮은 확인음 | 열차가 천천히 멈춤 |
| 전략 변경 가능 | 조절 레버가 점멸 | 부드러운 클릭음 | 카메라가 조절부로 이동 |
| 협동 동기화 | 두 빛줄기가 연결 | 화음 | 화면 가장자리 미세 진동 |
| 성공 | 도시 점등·길 개방 | 짧은 테마 음악 | 가벼운 햅틱 |

단, 색만으로 상태를 전달하지 말고, 아이콘·패턴·움직임·소리를 병행해야 합니다. Roblox 접근성 가이드도 충분한 텍스트-배경 대비와, 효과음·음악·음성 등 오디오 그룹별 조절 옵션을 권장합니다. [github](https://github.com/Roblox/creator-docs/blob/main/content/en-us/production/publishing/accessibility.md)

## 개인화는 ‘낙인’ 없이

과정 데이터를 이용해 피드백을 개인화할 수 있지만, 학생에게 수준을 공개하거나 고정된 능력 라벨을 붙이면 안 됩니다.

```text
피해야 할 것:
“초급반이라 쉬운 문제를 드립니다.”
“기울기 약점이 감지됐습니다.”
“당신은 하위 20%입니다.”

권장:
“이 구역의 신호가 조금 더 선명해졌어.”
“다음 탐험에서는 경로 단서가 먼저 보일 거야.”
“드론이 높이 변화를 함께 표시할게.”
```

### 내부 데이터 → 플레이어 표현

| 내부 신호 | 시스템 처리 | 플레이어에게 보이는 것 |
|---|---|---|
| 같은 좌표 순서 오류 2회 | 축 방향 힌트 우선 | “가로와 세로 빛을 함께 따라가 보자.” |
| 빠른 무힌트 성공 | 힌트 축소·변형 미션 | “새 경로도 시험해 볼래?” |

## UX 규격

### 피드백 카드

| 항목 | 권장 규칙 |
|---|---|
| 노출 시간 | 2~4초 후 축소, 플레이어 행동이 필요하면 유지 |
| 문장 수 | 1~2문장 |
| 문장 길이 | 각 문장 12~18단어 이내를 기준으로 현지화 여유 확보 |
| 버튼 수 | 기본 1개 |
| 위치 | 하단 중앙 또는 행동 대상 가까이, 핵심 월드 시야 방해 금지 |
| 색상 | 성공=청록/금색, 재조정=보라/노랑, 위험=색+아이콘 병행 |
| 애니메이션 | 짧고 줄일 수 있게, 카메라 흔들림 최소화 |
| 접근성 | 자막, 텍스트 크기, 대비, 소리/햅틱 개별 조절 |

Roblox는 UI가 장애가 있는 사용자도 사용할 수 있도록 대비를 확보하고, 사용자가 오디오와 투명도 같은 설정을 조절할 수 있도록 설계할 것을 권장합니다. [github](https://github.com/Roblox/creator-docs/blob/main/content/en-us/production/publishing/accessibility.md)

## 자동 검수 Harness

과정 피드백도 “문구가 나왔다”만 검사하면 부족합니다. 다음을 자동 테스트하세요.

```text
F01: 오답 시 1초 안에 결과가 월드에 나타나는가
F02: 피드백이 사람 평가가 아니라 행동·결과를 말하는가
F03: 피드백마다 다음 행동 버튼이 정확히 1개인가
F04: 재시도가 5초 안에 가능한가
F05: 첫 실패에 정답·전체 해설을 바로 주지 않는가
F06: 유사 실패가 반복되면 힌트 단계가 상승하는가
F07: 성공 시에도 사용한 전략을 언급하는가
F08: 개인별 수준·등수·약점 라벨을 외부에 노출하지 않는가
F09: 협동 실패가 특정 팀원을 비난하지 않는가
F10: 모바일에서 피드백 카드가 조이스틱·점프 버튼과 겹치지 않는가
F11: 색상만으로 핵심 상태를 표현하지 않는가
F12: 언어 변경 시 텍스트가 잘리지 않는가
F13: 소리·햅틱을 꺼도 시각 정보만으로 이해 가능한가
```

## 최종 원칙

수학 학습 게임의 과정 지향 피드백은 다음과 같은 말로 요약할 수 있습니다.

> **“너는 틀렸다”가 아니라, “방금 선택은 이런 결과를 만들었다. 다음에는 이 한 가지를 바꿔 보자.”**

수학마을에서는 그 피드백이 말풍선으로 끝나면 안 됩니다. 열차가 실제 다른 곳에 도착하고, 드론이 잘못된 신호를 비추고, 플레이어가 레버를 다시 조절하며, 게이트가 열리는 변화로 이어져야 합니다. 그렇게 하면 피드백은 평가가 아니라 **플레이어가 다음 실험을 하게 만드는 게임 메커닉**이 됩니다.
