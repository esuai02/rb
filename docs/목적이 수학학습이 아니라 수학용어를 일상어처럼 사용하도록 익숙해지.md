맞습니다. 이 게임의 핵심 목표를 \*\*“수학을 잘 푸는 아이를 선별하거나 훈련하는 것”이 아니라, 수학적 언어가 낯설지 않은 생활 언어가 되게 만드는 것\*\*으로 다시 고정해야 합니다.



즉 플레이어가 \\(x\\), 좌표, 변화량, 비율, 함수, 확률 같은 말을 시험 용어가 아니라 \*\*길을 안내하고, 친구와 협력하고, 도시를 고치고, 자기 생각을 표현하는 말\*\*로 쓰게 만드는 게임입니다. 이후 기획에서는 “정답률·난도·실력 향상”보다 \*\*수학 언어를 자발적으로 이해·선택·재사용하는가\*\*를 우선 지표로 보겠습니다.



이 목표는 앞서 만든 수학마을 세계관과 매우 잘 맞습니다. “수학마을 탐험 게이트”는 문제를 통과하는 관문이 아니라, 플레이어가 도시의 공통 언어를 익히는 첫 장소가 되어야 합니다.



\## 제품 목표 재정의



\### 기존에 흔히 생각하는 수학 게임



```text

문제 풀이

→ 정답/오답

→ 점수

→ 난도 상승

→ 수학 실력 향상

```



\### 이 게임이 지향할 구조



```text

도시에서 사건 발생

→ 수학 언어가 필요한 상황

→ 친구/드론/NPC와 그 언어를 듣고 사용

→ 월드가 반응

→ 같은 언어를 다른 맥락에서 다시 만남

→ “이 말은 쓸모 있는 말이구나”가 됨

```



| 구분 | 문제풀이형 수학 게임 | 수학 언어 친숙화 게임 |

|---|---|---|

| 핵심 목표 | 정답·풀이 정확도 | 용어의 자연스러운 이해·사용 |

| 플레이어 정체성 | 문제 해결자·시험 응시자 | 도시 탐험가·협동자·설계자 |

| 수학의 역할 | 통과 조건 | 공통 언어·행동 도구 |

| 실패 | 오답·점수 하락 | 말이 잘 안 통함·경로가 어긋남·다시 표현 |

| 보상 | 점수·정답 수·레벨 | 도시 변화·협동 성공·새 행동·표현권 |

| 난이도 | 계산 복잡도 상승 | 맥락 다양성·표현 선택 폭 증가 |

| 좋은 지표 | 정답률·풀이 시간 | 자발적 용어 선택·전이·협동 의사소통 |



\## 핵심 설계 원칙



\### 1. 용어를 먼저 정의하지 않는다



교과서식 시작은 피해야 합니다.



```text

“좌표란 평면 위 위치를 나타내는 순서쌍이다.”

```



대신 상황을 먼저 보여 줍니다.



```text

루미:

“드론이 신호를 찾으려면 위치를 두 개로 말해야 해.

먼저 옆으로, 다음은 위아래로.”



플레이어 행동:

오른쪽 2칸, 위로 1칸 위치를 드론에게 알려 줌.



성공 후:

“방금 말한 위치를 도시에서는 좌표라고 불러.”

```



정의는 행동 뒤에 붙는 \*\*이름표\*\*가 되어야 합니다.



```text

경험

→ 반복 사용

→ 이름 붙이기

→ 다른 상황에서 재사용

```



\### 2. 용어를 “정답”이 아니라 “선택 가능한 말”로 둔다



용어를 맞혀야 통과하게 만들면 다시 시험이 됩니다. 대신 플레이어가 말·아이콘·핑으로 상황을 표현할 수 있게 합니다.



예를 들어 드론 경로를 안내할 때:



```text

\[오른쪽으로]

\[위로]

\[더 가파르게]

\[같은 높이]

\[반대 방향]

\[절반씩 나누기]

\[다음 신호]

```



처음에는 일상어가 주로 보이고, 수학 언어가 괄호나 아이콘으로 함께 등장합니다.



```text

\[위로] (세로 위치 +)

\[더 가파르게] (기울기 ↑)

\[같은 높이] (y값 같음)

\[반대 방향] (음의 변화)

```



반복 노출 뒤에는 표현 순서를 바꿉니다.



```text

\[기울기 올리기] — 길을 더 가파르게 만들기

\[좌표 보내기] — 드론 위치 알려 주기

\[비율 맞추기] — 에너지를 공평하게 나누기

```



마지막에는 수학 용어가 자연스럽게 먼저 보여도 이해되는 상태를 목표로 합니다.



\### 3. “수학적 언어를 쓰면 팀이 더 잘 협력한다”



용어는 개인 시험보다 협동에서 가장 자연스럽게 익힙니다. 친구에게 “2번 답”을 말하게 하지 말고, 도시 작업에 필요한 짧은 언어로 안내하게 하세요.



| 도시 상황 | 일상 표현 | 자연스럽게 도입할 수학 언어 |

|---|---|---|

| 드론 위치 안내 | “오른쪽 두 칸, 위 한 칸” | 좌표, 가로축, 세로축 |

| 열차 경사 조절 | “이 길을 더 가파르게” | 기울기, 증가, 감소 |

| 에너지 배분 | “두 팀에 반반 나누자” | 비율, 전체, 부분 |

| 시장 물류 | “이 상자가 두 배 더 많아” | 배수, 비교, 단위 |

| 패턴 복구 | “이 조각을 돌려서 맞춰” | 회전, 대칭, 규칙 |

| 수상 구조 | “같은 속도로 가면 언제 만나?” | 거리, 시간, 속력 |

| 날씨 관측 | “오늘은 어제보다 얼마나 늘었어?” | 변화량, 그래프, 평균 |

| 랜덤 이벤트 | “이 보물 상자가 나올 가능성이 높아?” | 확률, 경우, 예측 |



중요한 점은 플레이어가 수학 용어를 쓰지 않으면 처벌하지 않는 것입니다. 다만 그 용어를 쓰거나 선택하면 \*\*더 짧고 명확하게 소통하고, 더 빠른 경로·더 좋은 협동 결과를 얻는 경험\*\*을 주면 됩니다.



\## 수학마을 게이트 재설계



기존 게이트 기획에서 “좌표 판단”과 “기울기 정답” 같은 표현을 약화하고, \*\*도시 언어를 발견하는 게이트\*\*로 바꾸는 것을 권합니다.



\### 게이트의 새 이름



```text

기존:

수학마을 탐험 게이트



추천:

도시 신호 언어 게이트

Math Village Signal Gate

```



\### 새 스토리



```text

Neo Seoul의 수학마을은 숫자를 잘 맞히는 사람만 들어가는 곳이 아니다.



도시의 길·열차·드론·빛 신호는

“위치, 방향, 변화, 나눔”의 언어를 알아들을 때 연결된다.



탐험가는 세 개의 도시 신호와 대화하며

도시가 쓰는 표현을 하나씩 배운다.

```



\### 3개 신호의 언어



| 신호 | 플레이 행동 | 처음 듣는 말 | 나중에 붙는 수학 이름 |

|---|---|---|---|

| 위치 신호 | 드론에게 목적지 전달 | “오른쪽 2, 위 1” | 좌표 |

| 변화 신호 | 열차 길을 조절 | “더 올라가게, 덜 내려가게” | 기울기·변화량 |

| 나눔 신호 | 팀 에너지 분배 | “둘이 똑같이, 세 팀은 이렇게” | 비율·분수 |



\#### 위치 신호 대사 예시



```text

루미:

“드론은 위치를 두 번 들어야 길을 알아.

옆으로 어디까지? 그리고 위아래로 어디까지?”



플레이어:

\[오른쪽 2] \[위로 1]



드론:

“위치를 받았어. 도시에서는 이런 위치 말을 ‘좌표’라고 불러.”



루미:

“어려운 말 같지만, 길을 정확히 알려 주는 별명이야.”

```



이것은 “좌표의 정의를 암기”하게 하는 것이 아니라, 플레이어가 이미 한 행동에 \*\*좌표라는 이름을 붙이는 방식\*\*입니다.



\## “수학 언어 사전” 대신 “도시 말 모음”



사전이나 용어장은 숙제처럼 보일 수 있습니다. 대신 탐험 카드 안에 \*\*도시 말 모음\*\*을 둡니다.



```text

City Language Atlas



위치 말

\[좌표]  드론과 열차에게 위치를 알려 주는 말

오늘 사용: 3회

새롭게 발견: “같은 가로 위치”



변화 말

\[기울기]  길이 얼마나 올라가거나 내려가는지 말하는 방법

오늘 사용: 1회

새롭게 발견: “음의 기울기”



나눔 말

\[비율]  전체를 어떻게 나눴는지 말하는 방법

오늘 사용: 2회

```



중요한 설계 원칙:



\- “정답률 80%”를 보여 주지 않기

\- “수학 레벨 5”를 경쟁적으로 노출하지 않기

\- 용어를 사용한 횟수도 무조건 많이 누른 횟수가 아니라, \*\*의미 있는 상황에서 성공적으로 선택·이해·재사용한 횟수\*\*만 기록

\- 다른 플레이어와 비교하지 않기

\- “약점”, “보충”, “하위” 같은 표현 사용 금지



\## 과정 피드백도 바꿔야 한다



앞서 말한 과정 지향 피드백은 “전략” 중심이었는데, 이제는 \*\*언어 사용의 자연스러움\*\*에도 초점을 둬야 합니다.



\### 기존 피드백



```text

“출발 위치와 경사를 함께 확인해서 정확히 연결했어.”

```



\### 언어 친숙화 피드백



```text

“방금 ‘더 가파르게’라고 말한 건,

도시 말로는 기울기를 바꾸는 거야.”



“두 위치를 차례대로 알려 줬어.

드론은 이런 위치 말을 좌표로 기억해.”



“팀에 ‘반반 나누자’고 알려 줬어.

그건 전체를 같은 비율로 나누는 방법이야.”

```



UI는 길게 설명하지 말고, 성공 후 1\~2초간 작은 \*\*언어 발견 태그\*\*만 띄웁니다.



```text

┌───────────────────────────┐

│ 새 도시 말 발견            │

│ \[좌표] 위치를 알려 주는 말 │

│                    +1      │

└───────────────────────────┘

```



`+1`은 점수가 아니라 “오늘 이 말을 실제로 써 봤다”는 기록이어야 합니다.



\## 언어 사용을 강요하지 않는 인터랙션



자유 채팅으로 수학 용어를 입력하게 하면 아동 안전·다국어·모더레이션 문제가 커집니다. 대신 \*\*상황별 표현 휠\*\* 또는 \*\*스마트 핑\*\*을 사용하세요.



\### 드론 위치 표현 휠



```text

\[위치 말하기]

&#x20; ├─ \[왼쪽] \[오른쪽]

&#x20; ├─ \[위] \[아래]

&#x20; ├─ \[가까이] \[멀리]

&#x20; ├─ \[같은 줄]

&#x20; └─ \[좌표 보기]

```



플레이어가 충분히 사용한 뒤에는:



```text

\[좌표]

&#x20; ├─ x 방향

&#x20; ├─ y 방향

&#x20; ├─ 같은 x

&#x20; └─ 같은 y

```



\### 경사 표현 휠



```text

\[길 조절]

&#x20; ├─ \[더 올라가게]

&#x20; ├─ \[더 내려가게]

&#x20; ├─ \[평평하게]

&#x20; └─ \[기울기 보기]

```



후반에는 다음처럼 자연스럽게 수학 용어 비중을 높입니다.



```text

\[기울기]

&#x20; ├─ 양의 기울기

&#x20; ├─ 음의 기울기

&#x20; ├─ 기울기 0

&#x20; └─ 더 가파르게

```



이 방식은 “정확한 수학 용어를 말해야 한다”가 아니라, \*\*일상어와 수학 언어가 같은 장면을 설명하는 두 가지 방식\*\*임을 보여 줍니다.



\## 성장 구조를 “실력”이 아니라 “표현의 폭”으로



성장 지표는 문제 난도를 푼 양이 아니라, 플레이어가 쓸 수 있는 언어의 폭으로 보여 주세요.



```text

견습 탐험가:

위치, 방향, 같은 곳



신호 안내자:

좌표, 가로/세로, 변화



길 설계자:

기울기, 증가/감소, 출발점



도시 조율자:

비율, 전체/부분, 비교



서울 사이버 시민:

상황에 맞는 도시 언어를 친구와 나누는 탐험가

```



여기서 “길 설계자”는 수학을 잘하는 우수생 칭호가 아니라, 플레이어가 게임 안에서 \*\*기울기라는 말을 보고·듣고·선택해서 실제로 써 본 경험\*\*이 쌓였다는 뜻입니다.



\## 새 Harness 지표



이 프로젝트의 목표가 바뀌면 자동 검수와 운영 지표도 바뀌어야 합니다.



\### 버려야 할 단독 KPI



\- 정답률만으로 성공 판정

\- 계산 속도

\- 어려운 문제 풀이 수

\- 타 플레이어 대비 순위

\- 힌트 미사용률만을 실력 지표로 해석

\- 수학 점수로 자격증·시민권 발급



\### 새 핵심 지표



| 지표 | 무엇을 뜻하는가 | 측정 예시 |

|---|---|---|

| 용어 첫 접촉 | 처음으로 개념을 맥락 속에서 만남 | `term\_exposed: coordinate` |

| 용어 이해 선택 | 용어/일상어 설명 중 의미 연결 | `term\_matched\_to\_action` |

| 자발적 용어 선택 | 강제되지 않았는데 용어 버튼·핑을 고름 | `term\_selected\_voluntarily` |

| 맥락 전이 | 다른 월드에서도 같은 용어를 사용 | 좌표: 드론 → 시장 물류 → 지도 |

| 협동 언어 사용 | 팀 목표에서 표현을 사용 | `team\_signal: slope\_up` |

| 언어-행동 정합 | 선택한 말과 실제 행동이 맞음 | “더 가파르게” → 상승 변화 증가 |

| 재방문 언어 | 다음 세션에 다시 용어를 선택 | D1/D7 term reuse |

| 정서 신호 | 실패 뒤에도 표현을 다시 시도 | 수정·재표현 비율 |



\### 언어 친숙화 점수: 공개하지 않는 내부 지표



내부적으로만 아래처럼 관리할 수 있습니다.



\\\[

L(t) =

w\_1 E(t) +

w\_2 R(t) +

w\_3 T(t) +

w\_4 C(t)

\\]



여기서,



\- \\(E(t)\\): 맥락 속 노출(Exposure)

\- \\(R(t)\\): 의미 있는 재사용(Reuse)

\- \\(T(t)\\): 다른 상황으로의 전이(Transfer)

\- \\(C(t)\\): 협동 의사소통에서의 선택(Communication)



하지만 플레이어에게는 숫자로 보여 주지 않습니다. 플레이어 화면에서는 “새 도시 말 발견”, “다른 구역에서도 써 봄”, “팀과 신호를 잘 나눔”처럼 정성적 표현으로만 보여 주세요.



\## 난이도도 다시 정의



이 게임에서 난이도는 계산이 복잡해지는 것이 아니라 \*\*언어의 추상성과 맥락의 다양성\*\*이 커지는 것입니다.



| 단계 | 플레이어가 듣는 언어 | 플레이어가 하는 일 |

|---|---|---|

| 1 | “위로”, “아래로”, “반반” | 몸으로 이동·버튼 선택 |

| 2 | “같은 줄”, “더 가파르게”, “두 배” | 월드에서 비교·조절 |

| 3 | “좌표”, “기울기”, “비율” | 일상어와 수학어 연결 |

| 4 | “같은 x값”, “음의 기울기”, “전체의 1/3” | 상황에 맞는 표현 선택 |

| 5 | “변화량”, “관계”, “예측” | 친구에게 설명·다른 월드에 전이 |



플레이어가 5단계 용어를 모른다고 해서 게임 진행을 막지 마세요. 더 쉬운 일상어 표현을 사용해도 항상 진행할 수 있어야 합니다. 수학 용어는 \*\*더 정확하고 더 짧고 더 강력한 도시 언어\*\*로 경험되어야 합니다.



\## 운영 원칙도 바꾸기



AI 에이전트에게 콘텐츠를 만들게 할 때 프롬프트의 성공 조건을 아래처럼 바꿔야 합니다.



```text

금지:

\- 수학 용어를 정의부터 설명할 것

\- 정답/오답 화면을 중심으로 설계할 것

\- 난도 상승을 계산량 증가로만 설계할 것

\- 수학 용어를 모르면 진입 불가로 만들 것

\- 점수/등수로 언어 능력을 공개할 것



필수:

\- 일상 상황에서 필요한 표현을 먼저 제시할 것

\- 행동 뒤에 수학 용어를 이름표처럼 연결할 것

\- 같은 용어를 최소 3개의 다른 맥락에서 재사용하게 할 것

\- 일상어와 수학어를 양방향으로 연결할 것

\- 혼자/친구와 모두 쓸 수 있는 안전한 표현 휠을 제공할 것

\- 실패를 ‘표현을 바꿔 볼 기회’로 만들 것

```



\## 가장 중요한 문장

> \*\*이 게임은 수학을 잘하는 아이만 빛나게 만드는 게임이 아니다.
