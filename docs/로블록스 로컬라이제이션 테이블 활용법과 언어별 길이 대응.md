Roblox `LocalizationTable`은 게임의 문구를 키 기반으로 관리하고, 플레이어의 로케일에 맞는 번역을 자동으로 반환하는 시스템입니다. 글로벌 수학 언어 게임에서는 “문장을 번역한다”보다 \*\*일상어 표현·수학 용어·동적 결과 문구를 분리하고, 언어별 길이에 따라 UI가 늘어나거나 재배치되도록 설계하는 것\*\*이 핵심입니다.



Roblox는 Creator Hub의 Localization에서 번역 테이블을 관리하고 CSV로 내려받아 수정·재업로드할 수 있게 지원합니다. 동적 값이 들어가는 문구는 번역 파라미터와 `Translator:FormatByKey()`로 처리할 수 있습니다. \[create.roblox](https://create.roblox.com/docs/production/localization/add-translations)



\## 기본 구조



```text

원본 문구/용어 정의

&#x20; ↓

LocalizationTable

&#x20; ├─ 키: term.slope.name

&#x20; ├─ 키: action.slope.increase

&#x20; ├─ 키: feedback.slope.too\_low

&#x20; └─ 키: ui.gate.progress

&#x20; ↓

플레이어 로케일별 Translator

&#x20; ↓

FormatByKey(key, parameters)

&#x20; ↓

TextLabel / TextButton / 동적 피드백 카드

```



\### 왜 키 기반인가



```lua

\-- 피해야 할 방식

label.Text = "목표보다 " .. difference .. "층 낮게 도착했어."



\-- 권장 방식

label.Text = translator:FormatByKey(

&#x20;   "feedback.slope.too\_low",

&#x20;   { floors = difference }

)

```



문장 순서, 복수형, 조사, 단위 위치가 언어마다 다르므로 코드에서 문장을 이어 붙이면 현지화 품질이 깨집니다.



```text

한국어:

목표보다 {floors}층 낮게 도착했어.



영어:

You arrived {floors} levels below the target.



일본어:

目標より{floors}階低い場所に着いたよ。

```



\## 테이블 설계



\### 1. 용어와 일상어를 분리



당신의 게임은 수학 용어를 일상어처럼 익히게 하는 것이므로, 같은 개념에 대해 최소 세 종류의 키를 둬야 합니다.



```text

term.slope.name

→ 기울기 / slope / 傾き



term.slope.short\_hint

→ 길의 올라감과 내려감을 말하는 방법

→ how much a path rises or falls

→ 道の上がり下がりを表す言葉



action.slope.increase

→ 더 올라가게

→ make it rise more

→ もっと上がるように



action.slope.flat

→ 같은 높이로

→ keep it level

→ 同じ高さにする

```



| 키 유형 | 용도 | 예 |

|---|---|---|

| `term.\*.name` | 수학 용어 이름 | `기울기`, `slope` |

| `term.\*.meaning` | 발견 태그·지도책 설명 | “길의 변화 정도” |

| `action.\*` | 플레이어 선택 표현 | “더 올라가게” |

| `feedback.\*` | 결과·재시도 안내 | “목표보다 낮게 도착했어” |

| `mission.\*` | 퀘스트 목표 | “열차 빛길을 연결하세요” |

| `team.\*` | 협동 핑 | “준비됨”, “여기로” |

| `ui.\*` | 버튼·HUD | “계속”, “닫기”, “진행도” |

| `accessibility.\*` | 설정·자막·대비 | “카메라 흔들림 줄이기” |



이렇게 분리하면 초반에는 `action.slope.increase`를 우선 보여 주고, 반복 노출 후 `term.slope.name`을 보조 또는 주 표기로 전환할 수 있습니다.



\### 2. 키는 문구가 아니라 의미로



```text

나쁜 키:

button\_text\_12

hello\_3

slope\_message\_new

ui\_thing



좋은 키:

action.slope.increase

feedback.slope.too\_low

term.coordinate.name

mission.gate.restore\_signal

team.ping.ready

```



키는 번역가·콘텐츠 에이전트·개발자가 모두 “이 문구가 어디서, 왜 쓰이는지” 알 수 있어야 합니다.



\### 3. Context와 Example을 넣기



같은 영어 단어도 문맥에 따라 번역이 다를 수 있습니다. CSV의 `Context`, `Example` 필드를 적극 사용하세요.



```csv

Key,Context,Example,ko-KR,en-US,ja-JP

term.slope.name,"수학 용어, 초등/중등용 도시 언어 태그","열차 길의 기울기","기울기","slope","傾き"

action.slope.increase,"플레이어가 경사 레버에서 선택하는 행동","길을 더 올라가게","더 올라가게","Make it rise more","もっと上がるように"

feedback.slope.too\_low,"열차가 목표보다 낮게 도착한 뒤 나오는 과정 피드백","목표보다 2층 낮게 도착","목표보다 {floors}층 낮게 도착했어","You arrived {floors} levels below the target.","目標より{floors}階低い場所に着いたよ。"

```



Creator Hub에서는 번역 테이블을 CSV로 다운로드·수정·업로드할 수 있으며, CSV에서는 번역뿐 아니라 `Key`, `Context`, `Example`도 관리할 수 있습니다. 테이블은 총 10,000개 항목, 파일 2MB, 한 번 업로드에서 추가·수정 1,000개라는 제한이 있으므로 대형 프로젝트는 용어팩/월드팩 단위로 나눠 운영하세요. \[create.roblox](https://create.roblox.com/docs/production/localization/add-translations)



\## LocalizationTable 설정



\### Creator Hub 방식



1\. Creator Hub에서 Experience를 선택합니다.

2\. \*\*Localization\*\* 메뉴로 이동합니다.

3\. 원본 언어와 대상 언어를 설정합니다.

4\. 자동 텍스트 캡처 또는 수동 소스 항목 추가를 사용합니다.

5\. \*\*Table Management\*\*에서 CSV를 다운로드합니다.

6\. 번역·Context·Example을 보완합니다.

7\. CSV를 업로드합니다.

8\. Studio Device Emulator에서 언어·화면 크기별로 검수합니다.



자동 번역은 빠른 초안에 쓸 수 있지만, 이 게임처럼 일상어와 수학 용어의 미묘한 연결이 핵심인 경우에는 우선 시장 언어별로 사람이 용어·말투를 검수해야 합니다.



\### Studio 내 테이블



`LocalizationTable` 인스턴스를 `LocalizationService` 아래 또는 게임이 검색할 수 있는 위치에 연결하고, UI 문자열을 테이블 항목과 연결합니다. `LocalizationService`는 플레이어 로케일에 맞는 번역 테이블을 찾아 자동 문자열 대체를 처리합니다. \[create.roblox](https://create.roblox.com/docs/reference/engine/classes/Translator)



\## Luau에서 번역 호출



\### Translator 가져오기



```lua

\-- StarterPlayerScripts/LocalizationController.lua



local LocalizationService = game:GetService("LocalizationService")

local Players = game:GetService("Players")



local player = Players.LocalPlayer



local translator = LocalizationService:GetTranslatorForPlayerAsync(player)

```



\### 키로 고정 텍스트 가져오기



```lua

local title = translator:FormatByKey("term.slope.name")

local meaning = translator:FormatByKey("term.slope.short\_hint")



termTitleLabel.Text = title

termMeaningLabel.Text = meaning

```



\### 동적 파라미터 문구



```lua

local feedbackText = translator:FormatByKey(

&#x20;   "feedback.slope.too\_low",

&#x20;   {

&#x20;       floors = 2,

&#x20;   }

)



feedbackLabel.Text = feedbackText

```



`Translator:FormatByKey()`는 Translator의 로케일에 해당하는 LocalizationTable에서 키를 찾아 번역 문자열을 반환하며, 두 번째 인수로 동적 파라미터를 채울 수 있습니다. \[create.roblox](https://create.roblox.com/docs/reference/engine/classes/Translator/FormatByKey)



\### 안전한 래퍼



번역 키가 누락돼도 게임 UI가 망가지지 않게 래퍼를 두세요.



```lua

\-- ReplicatedStorage/Shared/Localize.lua



local Localize = {}



function Localize.byKey(translator, key, args, fallback)

&#x20;   local ok, value = pcall(function()

&#x20;       return translator:FormatByKey(key, args or {})

&#x20;   end)



&#x20;   if ok and type(value) == "string" and value \~= "" then

&#x20;       return value

&#x20;   end



&#x20;   warn("Missing localization key:", key)

&#x20;   return fallback or key

end



return Localize

```



사용:



```lua

local Localize = require(game.ReplicatedStorage.Shared.Localize)



feedbackLabel.Text = Localize.byKey(

&#x20;   translator,

&#x20;   "feedback.coordinate.wrong\_vertical",

&#x20;   {},

&#x20;   "위아래 위치를 다시 확인해 보세요."

)

```



\## 동적 문구 규칙



\### 문장 조합을 코드에서 하지 않기



```lua

\-- 나쁜 예

label.Text = termName .. "을(를) 발견했어!"



\-- 좋은 예

label.Text = translator:FormatByKey(

&#x20;   "feedback.term\_discovered",

&#x20;   { term = translator:FormatByKey("term.slope.name") }

)

```



번역 테이블:



```text

ko-KR:

새 도시 말 발견: {term}



en-US:

New city word discovered: {term}



ja-JP:

新しい都市の言葉を発見：{term}

```



\### 수량·단위·시간도 키로



```text

ui.gate.progress

ko-KR: 게이트 신호 {current}/{total}

en-US: Gate signals {current}/{total}

ja-JP: ゲート信号 {current}/{total}



feedback.hint\_in\_seconds

ko-KR: {seconds}초 뒤 힌트를 보여 줄게.

en-US: A hint will appear in {seconds} seconds.

ja-JP: {seconds}秒後にヒントを表示するよ。

```



Creator Hub 문서는 타이머, 단위, 플레이어 이름처럼 게임 실행 중 변하는 내용은 LocalizationTable의 파라미터를 이용해 실시간으로 번역할 수 있다고 안내합니다. \[create.roblox](https://create.roblox.com/docs/production/localization/add-translations)



\## 언어별 길이 대응



번역에서 가장 흔한 UI 버그는 \*\*영어를 기준으로 고정 너비를 잡아 놓고, 독일어·러시아어·포르투갈어·프랑스어에서 문장이 넘치는 것\*\*입니다. 반대로 중국어·일본어·한국어는 단어 간 공백 구조가 달라 줄바꿈 규칙이 다르고, 아랍어·히브리어는 RTL을 고려해야 합니다.



\### 가장 중요한 원칙



```text

텍스트를 줄여서 UI에 억지로 맞추지 않는다.

UI가 텍스트와 기기에 맞춰 유연하게 변해야 한다.

```



\### 기본 조합



```text

ScreenGui

└─ SafeContainer

&#x20;  └─ FeedbackCard

&#x20;     ├─ UIPadding

&#x20;     ├─ UIListLayout

&#x20;     ├─ TitleLabel

&#x20;     ├─ BodyLabel

&#x20;     └─ ActionButton

```



\#### FeedbackCard 권장 속성



```lua

feedbackCard.AutomaticSize = Enum.AutomaticSize.Y

feedbackCard.Size = UDim2.new(0.86, 0, 0, 0)



feedbackCard.SizeConstraint = Enum.SizeConstraint.RelativeXX

```



\#### 본문 Label 권장 속성



```lua

bodyLabel.AutomaticSize = Enum.AutomaticSize.Y

bodyLabel.Size = UDim2.new(1, 0, 0, 0)



bodyLabel.TextWrapped = true

bodyLabel.TextXAlignment = Enum.TextXAlignment.Left

bodyLabel.TextYAlignment = Enum.TextYAlignment.Top

```



\#### 버튼 권장 속성



```lua

actionButton.AutomaticSize = Enum.AutomaticSize.XY

actionButton.TextWrapped = true

actionButton.TextScaled = false

```



`AutomaticSize`는 자식 콘텐츠 크기에 맞춰 UI 객체의 크기를 자동 조절할 수 있으며, 특히 현지화된 텍스트가 길어지는 경우에 유용합니다. `UISizeConstraint`와 `UITextSizeConstraint`를 함께 쓰면 기기마다 카드·텍스트가 지나치게 크거나 작아지는 것을 제한할 수 있습니다. \[create.roblox](https://create.roblox.com/docs/ui/size-modifiers)



\## `TextScaled`를 과신하지 않기



`TextScaled = true`만 켜면 긴 번역이 컨테이너에 맞게 계속 작아져, 작은 모바일에서 읽을 수 없을 정도로 줄어들 수 있습니다.



\### 권장



```text

\- 제목: 제한적 TextScaled + UITextSizeConstraint

\- 본문: 고정 범위 글자 크기 + TextWrapped + AutomaticSize.Y

\- 버튼: 최소 터치 높이를 지키고, 필요하면 2줄까지 허용

\- 카드: 세로로 늘어나도록 설계

```



```lua

local textConstraint = Instance.new("UITextSizeConstraint")

textConstraint.MinTextSize = 16

textConstraint.MaxTextSize = 28

textConstraint.Parent = titleLabel

```



Roblox 문서는 `AutomaticSize`로 현지화 텍스트에 맞춰 컨테이너를 확장하고, `UISizeConstraint`와 `UITextSizeConstraint`로 요소·글자 크기의 최소/최대를 제한하는 조합을 권장합니다. \[create.roblox](https://create.roblox.com/docs/ui/size-modifiers)



\## 레이아웃 패턴



\### 1. 버튼 하나가 길어지는 경우



```text

영어:

\[Adjust slope]



독일어:

\[Neigung erneut anpassen]



한국어:

\[기울기 다시 조절하기]

```



버튼에 고정 폭을 주지 말고, 최소/최대 폭을 둡니다.



```lua

actionButton.AutomaticSize = Enum.AutomaticSize.X

actionButton.Size = UDim2.fromOffset(120, 48)



local sizeConstraint = Instance.new("UISizeConstraint")

sizeConstraint.MinSize = Vector2.new(120, 48)

sizeConstraint.MaxSize = Vector2.new(320, 72)

sizeConstraint.Parent = actionButton

```



최대 폭을 넘으면 2줄 줄바꿈을 허용하거나, 모바일에서는 버튼을 카드 전체 폭으로 확장하세요.



\### 2. 제목 + 설명 + 행동 카드



```text

┌───────────────────────────────┐

│ 새 도시 말                     │

│                               │

│ 기울기: 길이 얼마나             │

│ 올라가거나 내려가는지 말해요.  │

│                               │

│ \[길 다시 조절하기]              │

└───────────────────────────────┘

```



권장:



```text

FeedbackCard

\- AutomaticSize.Y

\- Width: 화면의 80\~88%

\- Max width: PC에서도 과도하게 넓지 않게 제한

\- UIPadding: 모든 방향에 충분히

\- UIListLayout: 세로 배치

\- 버튼: 최소 높이 유지

```



\### 3. 표현 선택 휠은 언어 길이에 약함



“오른쪽으로”, “더 올라가게”처럼 짧은 표현은 괜찮지만, 어떤 언어는 길어져 원형 휠이 깨질 수 있습니다.



\*\*해결책:\*\*



```text

초반:

아이콘 중심 + 짧은 일상어



중간:

아이콘 + 한 줄 표현



후반:

수학 용어는 휠이 아니라 선택 뒤 태그/도구 설명으로 표시

```



예:



```text

휠 버튼:

↗

아래 작은 글씨: 올라가기



선택 뒤:

“더 올라가게 — 도시 말: 기울기 증가”

```



용어 전체를 작은 원형 버튼에 강제로 넣지 마세요.



\## RTL과 CJK 대응



\### RTL 언어



아랍어 등 RTL 언어는 최소한 다음을 별도 검수하세요.



```text

\- TextXAlignment가 오른쪽 정렬로 바뀌는가

\- 아이콘과 텍스트 순서가 자연스러운가

\- 진행도 `1/3`의 표시와 방향 화살표가 혼동되지 않는가

\- 좌/우 개념은 UI 정렬과 수학적 x방향을 혼동하지 않는가

\- 버튼 내부 여백이 반대로도 자연스러운가

```



특히 “왼쪽/오른쪽”을 수학 개념으로 쓰는 UI는 RTL 환경에서 위험합니다. 가능한 경우 다음처럼 절대 방향보다 \*\*월드 기준 기호·좌표축·색·아이콘\*\*을 병행하세요.



```text

텍스트만:

왼쪽으로 2칸



더 안전한 표현:

← 2칸

또는

x축 음의 방향 2칸

```



단, 초보자에게 처음부터 “x축 음의 방향”을 쓰지 말고, 월드의 고정 축 색상과 화살표를 보여 주면서 언어와 연결해야 합니다.



\### CJK 언어



한국어·일본어·중국어는 단어 경계 공백이 적고, 글꼴/줄바꿈이 영어와 다르게 동작합니다.



```text

\- 버튼에 너무 긴 한 줄 고정 금지

\- TextWrapped 켜기

\- 제목과 본문에 서로 다른 최대 줄 수 고려

\- 줄바꿈이 어색해도 의미가 깨지지 않는 짧은 문장 사용

\- 장식용 폰트보다 가독성 좋은 폰트 사용

```



\## 텍스트 길이를 줄이는 콘텐츠 규칙



UI 레이아웃만으로 해결하지 말고, 원문부터 짧고 구조적으로 써야 합니다.



\### 피드백 문장



```text

나쁜 원문:

“선택하신 경사 값은 목표로 설정된 승강장 고도에 도달하기에 충분하지 않았습니다.”



좋은 원문:

“목표보다 낮게 도착했어.”

```



\### 행동 버튼



```text

나쁜 원문:

“현재 선택한 경사 수치를 다시 조정합니다”



좋은 원문:

“경사 조절하기”

```



\### 협동 상태



```text

나쁜 원문:

“다른 팀 구성원이 반대편 신호 장치로 이동 중입니다.”



좋은 원문:

“팀원 신호 이동 중”

```



짧은 원문은 번역 품질, 화면 대응, 아동 가독성, UI 일관성을 모두 개선합니다.



\## 현지화 QA 매트릭스



자동 검수 Harness에는 언어별 스크린샷·레이아웃 테스트를 넣어야 합니다.



| 테스트 | 최소 언어 예시 | 확인 항목 |

|---|---|---|

| 긴 라틴 문자 | 독일어, 포르투갈어 | 버튼·카드 너비, 2줄 처리 |

| CJK | 한국어, 일본어, 중국어 | 줄바꿈, 글자 크기, 높이 |

| RTL | 아랍어 | 정렬, 아이콘 순서, 진행도 |

| 짧은 영어 | 영어 | 여백이 지나치게 비지 않는지 |

| 숫자/단위 | 모든 언어 | `{current}/{total}`, 거리, 시간 |

| 동적 닉네임 | 긴 사용자명 | 오버플로/잘림/필터링 |

| 소형 모바일 | 360px 폭 | 조이스틱·점프 버튼과 겹침 |

| 태블릿·PC | 넓은 화면 | 카드가 너무 넓거나 흩어지지 않음 |



\### 자동 검수 항목



```text

LOC01: 모든 사용 키가 LocalizationTable에 존재한다.

LOC02: fallback 키/문구가 없을 때 UI가 비어 있지 않다.

LOC03: 각 언어에서 TextBounds가 컨테이너를 넘지 않는다.

LOC04: 버튼 터치 영역이 최소 높이를 유지한다.

LOC05: FeedbackCard가 화면 안전 영역을 침범하지 않는다.

LOC06: 긴 문구에서 카드가 세로로 확장된다.

LOC07: 본문 글자가 최소 읽기 크기 아래로 축소되지 않는다.

LOC08: RTL에서 텍스트·아이콘·패딩 방향이 맞는다.

LOC09: 동적 파라미터가 언어별 문장에 올바르게 삽입된다.

LOC10: 용어 이름과 일상어 표현이 언어별 용어집과 일치한다.

```

```text

curriculum/

```



\- \*\*용어집:\*\* `slope`, `coordinate`, `ratio`의 공식·교육적 표현

\- \*\*게임 번역:\*\* NPC 말투, 버튼, 미션, 피드백

\- \*\*현지화 테이블:\*\* Roblox UI 표시용 키/문구



이 세 가지를 한 파일에 섞으면 번역은 빨라져도 교육적 일관성이 무너질 수 있습니다.



\### 번역 우선순위



1\. 게임 진행을 막는 UI: Prompt, 버튼, 경고, 목표  

2\. 도시 언어 표현: 일상어·수학어 연결  

3\. 피드백·힌트  

4\. NPC 대사  

5\. 수집 앨범·장식 텍스트  

6\. 마케팅 문구·설명  



자동번역은 4\~6번 초안에는 유용할 수 있지만, 1\~3번은 현지 교육·언어 검수가 필요합니다.



\## 결론



Roblox LocalizationTable을 제대로 쓰는 방식은 다음입니다.



```text

하드코딩 문장

→ 의미 기반 키



문자열 이어 붙이기

→ FormatByKey + 파라미터



고정 폭 UI

→ AutomaticSize + TextWrapped + Layout + Constraints



영어 기준 UI

→ 긴 언어·CJK·RTL·소형 모바일을 포함한 QA



단순 번역

→ 일상어 표현과 수학 용어를 분리한 현지 언어 설계

```



당신의 게임에서 가장 중요한 UI 원칙은 이것입니다.



> \*\*언어가 길어져도 버튼이 작아지거나 의미가 잘리면 안 된다.  

> 플레이어는 자신의 언어로 ‘더 올라가게’, ‘반반 나누자’, ‘이 좌표로 가자’를 자연스럽게 말하고, 그 뒤에 수학적 언어를 발견해야 한다.\*\*
