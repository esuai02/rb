`ProximityPrompt`는 수학마을의 게이트, 신호 패널, 경사 콘솔, NPC, 자격증 보드처럼 **월드 안의 오브젝트와 UI 피드백을 연결하는 가장 좋은 기본 인터랙션 수단**입니다. 플레이어가 가까이 가면 기기별 적절한 입력 힌트가 나타나고, 상호작용 결과는 서버에서 검증한 뒤 동적 피드백 UI와 월드 연출로 이어지게 설계하세요.

Roblox의 기본 Prompt는 키보드·게임패드·터치 입력을 자동으로 표시하며, 즉시 탭/클릭 또는 길게 누르기, 표시 거리, 문구 등을 설정할 수 있습니다. 대규모 게임에서는 각 Prompt에 스크립트를 붙이기보다 `ProximityPromptService`로 전역 처리하는 편이 유지보수에 유리합니다. [create.roblox](https://create.roblox.com/docs/ui/proximity-prompts)

## 기본 설계

```text
플레이어가 오브젝트에 접근
  ↓
ProximityPrompt 표시
  ↓
플레이어가 탭/키/게임패드 버튼으로 상호작용
  ↓
서버가 거리·퀘스트 상태·순서·보상 가능 여부 검증
  ↓
월드 상태 변경 + RemoteEvent로 검증 결과 전달
  ↓
클라이언트:
- 동적 피드백 카드
- 오브젝트 하이라이트
- 사운드·햅틱·애니메이션
- 다음 행동으로 유도
```

### 수학마을 프롬프트 분류

| 오브젝트 | Prompt 문구 | 입력 방식 | 게임 역할 |
|---|---|---|---|
| 신호 패널 | `신호 켜기` | 즉시 탭 | 첫 상호작용·즉시 성공 |
| 좌표 드론 콘솔 | `드론 경로 설정` | 즉시 탭 | 좌표·방향 미션 시작 |
| 경사 레버 | `경사 조절` | 즉시 탭 | 과정 피드백 후 재조절 |
| 협동 프리즘 스위치 | `신호 준비` | 0.4~0.8초 홀드 | 팀 동기화 |
| NPC 루미 | `도움 요청` | 즉시 탭 | 지연 힌트·재설명 |
| 자격증 게시판 | `의뢰 보기` | 즉시 탭 | 다음 미션 선택 |
| 포털 | `Metro District로 이동` | 0.5초 홀드 | 지역 이동·오작동 방지 |

처음 5분 온보딩에서는 행동 동작을 너무 다양하게 만들지 마세요. 기본값은 **즉시 탭**이고, “협동 스위치”나 “포털 이동”처럼 의도적 행동을 보여 주고 싶은 곳에만 짧은 홀드를 씁니다.

## Prompt 속성 설정

### 기본 예시

```lua
-- Workspace/MathVillage/SignalPanelAlpha/ProximityPrompt
local prompt = Instance.new("ProximityPrompt")

prompt.Name = "SignalActivatePrompt"
prompt.ActionText = "신호 켜기"
prompt.ObjectText = "게이트 신호"
prompt.KeyboardKeyCode = Enum.KeyCode.E
prompt.GamepadKeyCode = Enum.KeyCode.ButtonX

prompt.MaxActivationDistance = 10
prompt.MaxIndicatorDistance = 18
prompt.HoldDuration = 0
prompt.ClickablePrompt = true

prompt.RequiresLineOfSight = false
prompt.Style = Enum.ProximityPromptStyle.Default

prompt.Parent = workspace.MathVillage.SignalPanelAlpha
```

| 속성 | 권장값 | 이유 |
|---|---|---|
| `ActionText` | 행동 동사 2~4단어 | “신호 켜기”, “경사 조절”처럼 즉시 이해 |
| `ObjectText` | 대상 이름 | “게이트 신호”, “드론 콘솔” |
| `MaxActivationDistance` | 8~12 studs | 너무 가까이 붙지 않아도 모바일에서 편함 |
| `MaxIndicatorDistance` | 15~25 studs | 목표를 미리 알아차릴 수 있음 |
| `HoldDuration` | 기본 0초 | 온보딩 마찰 최소화 |
| `ClickablePrompt` | `true` | 모바일·마우스 접근성 보조 |
| `RequiresLineOfSight` | 보통 `false` | 장식·NPC·투명 오브젝트에 가려져 프롬프트가 사라지는 문제 방지 |
| `Style` | 초기에는 `Default` | 플랫폼 표준 UI와 입력 힌트를 그대로 활용 |

`ProximityPrompt`는 `BasePart`, `Attachment`, 또는 `PrimaryPart`가 있는 `Model`의 자식에 둘 수 있습니다. `ActionText`, `ObjectText`, 키보드/게임패드 키, 최대 거리, 홀드 시간, 클릭 가능 여부를 조절할 수 있습니다. [create.roblox](https://create.roblox.com/docs/ui/proximity-prompts)

## 온보딩용 Prompt 플로우

### 신호 1: 첫 즉시 성공

```text
거리 18 studs:
- 패널 외곽이 청록색으로 약하게 점등
- 기본 Prompt는 아직 안 보이거나 작게 표시

거리 10 studs:
- [E] 신호 켜기 / [탭] 신호 켜기 표시
- 목표 HUD: “게이트 신호를 켜세요.”

상호작용:
- 패널이 바로 점등
- 게이트 진행도 1/3
- 피드백 카드: “좋아! 첫 신호가 깨어났어.”
- 다음 드론 콘솔이 빛남
```

첫 프롬프트에는 홀드를 쓰지 마세요. 첫 행동은 확실하고 즉시 성공해야 합니다.

### 신호 2: 미션 진입

```text
드론 콘솔 가까이:
[드론 경로 설정]

상호작용:
- UI 카드가 아니라 작은 월드 지도 패널 열림
- 3개 플랫폼 중 하나를 월드에서 선택
- 선택 결과는 서버가 판정
```

여기서 `ProximityPrompt`는 “문제를 푸는 버튼”이 아니라, **수학적 행동이 일어나는 공간으로 들어가는 문**입니다.

### 신호 3: 협동

```text
프리즘 스위치:
[길게 누르기: 신호 준비]

플레이어가 홀드:
- 스위치 빛이 점점 차오름
- HUD에 “나: 준비됨”
- 친구/NPC 반대편 스위치 상태 표시

둘이 3초 창 안에서 활성화:
- 빛줄기 연결
- 게이트 신호 3/3
```

협동 스위치에만 `HoldDuration = 0.5` 정도를 사용하면, 플레이어가 “나는 지금 팀을 위해 신호를 유지하고 있다”는 감각을 받습니다. 단, 홀드 시간을 길게 잡으면 모바일에서 피로하므로 1초를 넘기지 않는 편이 좋습니다.

## 서버 라우터: Prompt를 한곳에서 처리

각 Prompt마다 Script를 따로 넣으면 월드가 커질수록 규칙이 흩어집니다. 태그 또는 Attribute를 이용해 `ProximityPromptService`에서 전역 라우팅하세요.

### Prompt에 Attribute 부여

```lua
-- Studio 또는 생성 코드에서 설정
prompt:SetAttribute("InteractionId", "signal_1_activate")
prompt:SetAttribute("QuestId", "math_village_gate")
prompt:SetAttribute("RequiredState", "MOVE_TO_SIGNAL_1")
prompt:SetAttribute("NextState", "SIGNAL_1_DONE")
prompt:SetAttribute("FeedbackId", "signal_1_success")
```

### 서버 라우터 예시

```lua
-- ServerScriptService/PromptRouter.server.lua
local ProximityPromptService = game:GetService("ProximityPromptService")
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local FeedbackEvent = ReplicatedStorage.Remotes.FeedbackEvent

local GateService = require(script.Parent.GateService)
local PlayerStateService = require(script.Parent.PlayerStateService)

local handlers = {}

handlers.signal_1_activate = function(player, prompt)
    local state = PlayerStateService:getState(player)

    if state ~= "MOVE_TO_SIGNAL_1" then
        return
    end

    if not GateService:isPlayerNearPrompt(player, prompt, 14) then
        return
    end

    if not GateService:activateSignal(player, "signal_1") then
        return
    end

    PlayerStateService:setState(player, "SIGNAL_1_DONE")

    FeedbackEvent:FireClient(player, {
        eventId = "signal_1_success",
        kind = "success",
        severity = 0,
        titleKey = "feedback.signal_1.title",
        bodyKey = "feedback.signal_1.body",
        progress = { current = 1, total = 3 },
        visual = {
            targetId = "GateRing_01",
            color = "teal",
            effect = "activate",
        },
        duration = 2.8,
    })
end

ProximityPromptService.PromptTriggered:Connect(function(prompt, player)
    local interactionId = prompt:GetAttribute("InteractionId")
    local handler = interactionId and handlers[interactionId]

    if not handler then
        return
    end

    handler(player, prompt)
end)
```

`ProximityPromptService`는 모든 Prompt의 `PromptShown`, `PromptHidden`, `PromptTriggered`, 홀드 시작/종료 이벤트를 전역적으로 처리할 수 있습니다. Prompt마다 중복 코드가 생기는 것을 줄이는 데 유용합니다. [create.roblox](https://create.roblox.com/docs/ui/proximity-prompts)

### 반드시 추가할 서버 검증

`PromptTriggered`는 유용하지만, 보상·진도·자격증을 지급하는 코드에서는 아래를 서버에서 다시 확인하세요.

```text
- 해당 플레이어가 현재 미션 단계에 있는가
- Prompt가 아직 활성 상태인가
- 플레이어 캐릭터가 실제 상호작용 거리 안에 있는가
- 이전 상태를 완료하지 않고 다음 단계 Prompt를 누르지 않았는가
- 동일 Prompt를 연타해 완료·보상이 중복되지 않는가
- 협동이라면 팀·시간 창·역할 조건이 충족되는가
```

Prompt 이벤트 하나만으로 “시민 견습 배지 지급”을 처리하지 말고, 상태 머신을 통과한 뒤 `RewardService`가 **한 번만** 지급하게 하세요.

## Custom Prompt UI: 언제 쓸까

처음에는 기본 `Default` 스타일을 권장합니다. 입력 기기별 버튼 안내가 자동이고, 모바일·게임패드 호환성을 쉽게 얻을 수 있기 때문입니다.

다만 다음 상황에서는 `Style = Custom`이 적합합니다.

- Neo Seoul의 단청·네온 아트 스타일을 강하게 반영해야 할 때
- 협동 스위치에 팀 준비 상태·동기화 게이지를 보여 줄 때
- 수학적 피드백과 Prompt를 한 UI 계층으로 연결해야 할 때
- NPC/드론 근처에 특정 역할 아이콘·거리·신호 상태를 보여 줄 때
- 기본 UI만으로는 “다음 행동”을 설명하기 어려울 때

Roblox는 `ProximityPromptStyle.Custom`을 설정하고 LocalScript에서 커스텀 UI를 생성하는 예시를 제공합니다. Custom으로 바꾸면 기본 인터페이스가 사라지므로, 표시·입력·홀드 진행·모바일 클릭을 직접 구현해야 합니다. [create.roblox](https://create.roblox.com/docs/reference/engine/enums/ProximityPromptStyle)

## Custom Prompt UI 예시

### 구조

```text
StarterGui
  └─ PromptGui
      └─ PromptBillboardTemplate
          ├─ ActionLabel
          ├─ ObjectLabel
          ├─ KeyHint
          ├─ HoldRing
          ├─ TeamStatus
          └─ InputButton

StarterPlayer
  └─ StarterPlayerScripts
      └─ CustomPromptController.client.lua
```

### Custom 모드 Prompt

```lua
prompt.Style = Enum.ProximityPromptStyle.Custom
prompt.ActionText = "신호 준비"
prompt.ObjectText = "프리즘 스위치"
prompt.HoldDuration = 0.6
prompt.ClickablePrompt = true
```

### 표시·숨김 처리

```lua
-- StarterPlayerScripts/CustomPromptController.client.lua
local ProximityPromptService = game:GetService("ProximityPromptService")
local Players = game:GetService("Players")

local playerGui = Players.LocalPlayer:WaitForChild("PlayerGui")
local template = playerGui.PromptGui.PromptBillboardTemplate

local activePrompts = {}

local function createPromptGui(prompt, inputType)
    local clone = template:Clone()
    clone.Name = "Prompt_" .. prompt:GetDebugId()
    clone.Adornee = prompt.Parent
    clone.ActionLabel.Text = prompt.ActionText
    clone.ObjectLabel.Text = prompt.ObjectText
    clone.Enabled = true
    clone.Parent = playerGui

    if inputType == Enum.ProximityPromptInputType.Touch then
        clone.KeyHint.Text = "탭"
    else
        clone.KeyHint.Text = prompt.KeyboardKeyCode.Name
    end

    activePrompts[prompt] = clone
end

local function removePromptGui(prompt)
    local gui = activePrompts[prompt]
    if gui then
        gui:Destroy()
        activePrompts[prompt] = nil
    end
end

ProximityPromptService.PromptShown:Connect(function(prompt, inputType)
    if prompt.Style ~= Enum.ProximityPromptStyle.Custom then
        return
    end

    createPromptGui(prompt, inputType)
end)

ProximityPromptService.PromptHidden:Connect(function(prompt)
    removePromptGui(prompt)
end)
```

### 홀드 진행도

```lua
local TweenService = game:GetService("TweenService")

ProximityPromptService.PromptButtonHoldBegan:Connect(function(prompt)
    local gui = activePrompts[prompt]
    if not gui then
        return
    end

    gui.HoldRing.Progress.Size = UDim2.fromScale(0, 1)

    TweenService:Create(
        gui.HoldRing.Progress,
        TweenInfo.new(prompt.HoldDuration, Enum.EasingStyle.Linear),
        { Size = UDim2.fromScale(1, 1) }
    ):Play()
end)

ProximityPromptService.PromptButtonHoldEnded:Connect(function(prompt)
    local gui = activePrompts[prompt]
    if gui then
        gui.HoldRing.Progress.Size = UDim2.fromScale(0, 1)
    end
end)
```

홀드 시간은 `PromptButtonHoldBegan`, `PromptButtonHoldEnded`, `PromptTriggered`를 조합해 시각화할 수 있습니다. 공식 문서도 이러한 이벤트를 `ProximityPromptService`에서 제공한다고 설명합니다. [create.roblox](https://create.roblox.com/docs/ui/proximity-prompts)

### 주의: Custom UI의 클릭 처리

Custom Prompt는 기본 프롬프트의 자동 입력 처리를 직접 대체합니다. 따라서 모바일에서 `TextButton`/`ImageButton`을 썼다면 버튼 클릭, 홀드 시작·종료, 키보드·게임패드 입력을 직접 연결해야 합니다. 단순히 `Style = Custom`으로만 바꾸면 터치 사용자가 Prompt를 실행하지 못할 수 있습니다. [devforum.roblox](https://devforum.roblox.com/t/custom-proximity-prompt-does-not-work-for-mobile-users/4482829)

그래서 MVP에서는 다음처럼 나누는 편이 안전합니다.

```text
기본 Prompt:
- 신호 1
- 드론 콘솔
- NPC 도움
- 포털
- 의뢰 게시판

Custom Prompt:
- 협동 프리즘 스위치
- 경사 조절 레버
- 특별 이벤트·보스·시민권 발급 같은 핵심 연출
```

## Prompt와 동적 피드백을 연결하는 패턴

### 패턴 A: 성공형

```text
[신호 켜기]
→ 서버 검증
→ 패널 점등
→ 게이트 링 1/3 회전
→ UI: “첫 신호가 깨어났어.”
→ 다음 Prompt 강조
```

### 패턴 B: 과정 피드백형

```text
[경사 조절]
→ 플레이어가 값 선택
→ 서버 판정: 목표보다 낮음
→ 열차가 낮은 플랫폼에 도착
→ UI: “목표보다 낮게 도착했어.”
→ [경사 다시 조절하기]
→ 해당 Prompt/레버 강조
```

### 패턴 C: 협동형

```text
[신호 준비] 홀드
→ UI: “나: 준비됨”
→ 친구/NPC 상태: “신호 연결 중”
→ 3초 허용 창
→ 성공: 두 빛줄기 연결
→ UI: “팀 신호가 연결됐어!”
```

### 패턴 D: 막힘 회복형

```text
플레이어가 15초간 다음 Prompt에 접근하지 않음
→ 다음 Prompt 외곽선 점멸
→ 드론이 목적지 방향으로 이동
→ HUD: “빛나는 패널로 가 보자.”
→ 10초 더 막힘
→ NPC 도움 Prompt 활성화
```

이 구조에서 Prompt는 “눌러야 하는 버튼”, 동적 피드백은 “왜 다음 행동을 해야 하는지”, 월드 연출은 “그 행동이 어떤 변화를 만들었는지”를 각각 담당합니다.

## UX 규칙

### Prompt 문구

```text
좋음:
신호 켜기
경사 조절
드론 경로 설정
도움 요청
의뢰 보기
게이트 열기

나쁨:
상호작용
계속
확인
수학 문제 풀기
정답 제출
NPC와 대화하기
```

- `ActionText`: 짧은 동사 + 목적어
- `ObjectText`: 고유 이름보다 기능 이름 우선
- 첫 화면에는 Prompt를 하나만 활성화
- 동시에 여러 개가 보이면 가장 중요한 것만 높은 우선순위로 강조
- 첫 Prompt는 짧은 탭, 고위험 행동만 짧은 홀드
- 화면 하단 기본 이동·점프 영역과 커스텀 UI가 겹치지 않게 배치

### 표시 거리

```text
목표 오브젝트:
MaxIndicatorDistance 18~25

실제 조작:
MaxActivationDistance 8~12

협동 스위치:
MaxActivationDistance 6~8
```

너무 먼 거리에서 “신호 켜기”가 보이면 플레이어는 눌러도 반응하지 않아 혼란을 느낍니다. 반대로 너무 가까워야 보이면 작은 모바일 화면에서 오브젝트를 찾기 어렵습니다. **먼 거리에는 목적지 단서, 가까운 거리에는 조작 Prompt**를 분리하세요.

## 접근성·현지화

- `ActionText`와 `ObjectText`는 현지화 테이블로 관리
- 색상만으로 상호작용 가능 여부를 표현하지 않기
- 키 아이콘 외에도 동사 텍스트 표시
- 홀드에는 원형 진행도 + 남은 시간/채움 애니메이션 제공
- 터치·키보드·게임패드 모두에서 같은 행동 가능
- 강한 진동·번쩍임은 설정에서 줄일 수 있게 하기
- 세계관 고유 용어는 처음에 기능 설명과 함께 제시  
  예: `프리즘 스위치 — 신호를 함께 연결합니다`
- 긴 번역에서 `ObjectText`가 잘려도 핵심 `ActionText`가 남도록 레이아웃 설계

ProximityPrompt는 기기 입력에 맞는 버튼 힌트를 자동 표시할 수 있으며, `ClickablePrompt`를 켜면 클릭/탭으로도 실행할 수 있습니다. Custom UI에서는 이 동작을 직접 구현·테스트해야 합니다. [create.roblox](https://create.roblox.com/docs/ui/proximity-prompts)

## 자동 QA 체크리스트

```text
P01: 첫 온보딩 구간에 활성 Prompt가 하나만 보인다.
P02: Prompt가 활성 거리 밖에서는 Trigger되지 않는다.
P03: Prompt가 보일 때 ActionText와 ObjectText가 올바르게 현지화된다.
P04: 터치·키보드·게임패드 각각에서 실행된다.
P05: ClickablePrompt가 모바일에서 실제로 탭된다.
P06: HoldDuration이 있는 Prompt는 취소 시 진행도가 초기화된다.
P07: Prompt 연타로 신호·보상·진도가 중복 처리되지 않는다.
P08: 잘못된 퀘스트 상태에서 Trigger하면 서버가 처리하지 않는다.
P09: 팀원 이탈 시 협동 Prompt가 NPC 대체로 전환된다.
P10: 다음 Prompt는 이전 단계 성공 뒤에만 활성화된다.
P11: Custom Prompt UI는 PromptHidden에서 반드시 제거된다.
P12: 360×800 화면에서 Prompt와 피드백 카드가 조이스틱·점프 버튼과 겹치지 않는다.
P13: 긴 언어 번역, RTL 언어에서 Prompt가 잘리지 않거나 반전 오류가 없다.
P14: 시각 효과·사운드를 꺼도 텍스트/입력 힌트만으로 행동을 이해할 수 있다.
```

## MVP 권장안

처음에는 **기본 Prompt + 전역 서버 라우터 + 동적 피드백 카드**만 구현하세요.

```text
MVP:
- SignalPanelAlpha: 기본 Prompt, 즉시 성공
- DroneConsole: 기본 Prompt, 좌표 미션 진입
- PrismSwitch: 기본 Prompt, 짧은 홀드
- LumiNPC: 기본 Prompt, 도움 요청
- PromptRouter: ProximityPromptService 전역 처리
- FeedbackEvent: 서버 결과를 클라이언트 UI로 전달
- WorldHighlight: 다음 오브젝트 강조
```

Custom Prompt UI는 협동 신호 게이지나 시민권 발급 연출처럼, 기본 Prompt로는 표현이 부족하다는 것이 실제 데이터로 확인된 뒤 추가하세요.

## 결론

`ProximityPrompt`를 단순 “E 키 누르기” 도구로 쓰지 말고 아래처럼 역할을 분리하면 좋습니다.

```text
ProximityPrompt:
지금 만질 수 있는 오브젝트와 입력을 알려 준다.

서버 상태 머신:
그 행동이 지금 가능한지·올바른지·보상을 줄지 결정한다.

동적 피드백 UI:
방금 결과와 다음 조절 행동을 알려 준다.

월드 연출:
선택이 도시를 실제로 바꿨음을 보여 준다.
```

수학마을에서 플레이어는 `[신호 켜기]`를 누르는 것이 아니라, **도시의 신호를 복구하고 다음 실험으로 나아가는 행동**을 하게 됩니다.
