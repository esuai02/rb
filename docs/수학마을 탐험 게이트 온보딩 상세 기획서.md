아래 기획은 “수학마을 탐험 게이트”를 단순 튜토리얼이 아니라, 플레이어가 **처음으로 도시를 복구하고 시민 견습생이 되는 5분짜리 협동 어드벤처**로 설계한 상세안입니다. 목표는 수학을 가르쳤다고 느끼게 하는 것이 아니라, 플레이어가 “나는 이 세계에서 움직이고, 판단하고, 친구와 함께 게이트를 열 수 있다”는 감각을 얻는 것입니다.

Roblox의 FTUE 가이드는 첫 몇 분이 게임의 인터페이스·핵심 메커닉·세계관을 전달하는 구간이며, 시각 안내·맥락형 튜토리얼·진행이 멈췄을 때만 나오는 지연 힌트가 이탈을 줄이는 핵심 수단이라고 설명합니다. [create.roblox](https://create.roblox.com/docs/production/game-design/onboarding)

## 2. 세계관과 화면

### 배경

Neo Seoul Central은 미래 서울풍 교통 허브입니다. 멀리에는 네온 빌딩, 한강 방향의 빛, 단청에서 영감받은 청록·금색 패턴이 보입니다. 중앙에는 비활성 상태의 거대한 원형 게이트가 있고, 그 너머로 수학마을의 탑·열차·패턴 궁전이 희미하게 보입니다.

게이트는 현실 국경이나 출입국 심사 시설이 아닙니다. 게임 내에서는 **도시 탐험 신호를 동기화하는 고대-미래형 포털**입니다.

### 핵심 NPC

| 요소 | 이름 | 역할 | 말투 |
|---|---|---|---|
| 안내 NPC | 루미 | 짧은 안내, 힌트, 안전한 격려 | 친절하고 빠름 |
| 보조 NPC | 라인 드론 | 혼자일 때 협동 역할 대체 | 말보다 빛·움직임 |
| 게이트 | Seoul Signal Gate | 미션 목표·보상 시각화 | 점등·회전·개방 |

### 첫 등장 대사

```text
루미:
“탐험가, 수학마을 게이트가 멈췄어.
신호 세 개만 되살리면 길이 열려!”

[게이트 신호 복구하기]
```

이후에는 텍스트를 최소화합니다. 플레이어가 버튼을 누르지 않아도 2초 뒤 바닥에 청록색 빛 경로가 나타나고, 라인 드론이 첫 목적지로 날아갑니다.

### UI 구조

```text
┌──────────────────────────────────────────────────┐
│ [게이트 신호 복구]       1 / 3         [⚙]       │
│                                                  │
│               월드 안의 게이트·경로·드론          │
│                                                  │
│ [작은 목표 핑]                      [상호작용]   │
│ [기본 이동]                           [점프]     │
└──────────────────────────────────────────────────┘
```

상시 HUD는 다음 세 개만 유지합니다.

- 좌상단: `게이트 신호 복구 1/3`
- 상단 중앙: 팀 신호 에너지 또는 진행도
- 우상단: 일시정지·설정

인벤토리, 상점, 시민권 컬렉션, 출석 보상, 친구 목록은 이 온보딩에서 숨깁니다.

## 4. 단계별 상세 기획

### Phase A — 도착과 목표 제시

**목표:** 10초 안에 “가야 할 곳”과 “왜 가는지”를 이해시킵니다.

```text
스폰 위치:
게이트 정면에서 약 35~45 스터드 앞.

카메라:
게이트를 중심으로 1.2초간 부드럽게 보여 준 뒤,
플레이어 조작권을 즉시 반환.

월드 단서:
- 게이트: 꺼진 청록 링 3개
- 첫 신호: 멀리서 깜빡이는 노랑 패널
- 경로: 바닥 청록 선 + 작은 화살표
- 드론: 첫 신호 위로 이동
```

#### 규칙

- 강제 컷신은 2초 이내
- 버튼을 눌러야 게임이 시작되는 구조 금지
- NPC 대화는 첫 문장만 자동 노출
- 5초 동안 이동 입력이 없을 때만 이동 힌트 노출
- 길 안내는 화면 화살표보다 월드 바닥 빛을 우선

#### 지연 힌트

| 조건 | 힌트 |
|---|---|
| 5초 이동 입력 없음 | “빛나는 길을 따라가 보세요.” |
| 10초 목적지 반대 방향 이동 | 드론이 플레이어 쪽으로 돌아와 경로 재표시 |
| 15초 진행 없음 | 화면 가장자리 방향 화살표 + 목적지 거리 |
| 25초 진행 없음 | 카메라를 부드럽게 게이트/첫 신호 방향으로 보정 |

### Phase B — 신호 1: 움직이면 세계가 반응한다

**목표:** 근접 상호작용과 즉시 보상을 가르칩니다.

```text
오브젝트:
Signal Panel Alpha

상호작용:
ProximityPrompt
텍스트: [신호 켜기]

성공:
- 패널 점등
- 게이트 첫 번째 링이 회전
- 1/3 진행 표시
- 짧은 햅틱/사운드
- 라인 드론이 두 번째 구역으로 이동
```

루미의 반응:

```text
“좋아! 네 움직임이 게이트에 닿았어.”
```

이 문장은 1.5초 이내 자동 사라집니다.

#### 실패 설계

실패가 없어야 합니다. 패널은 누르면 항상 작동합니다. 첫 상호작용에서 실패를 주면 신규 이용자가 조작 자신감을 잃습니다.

### Phase C — 신호 2: 좌표를 ‘위치’로 경험

**목표:** 수학적 판단을 객관식 문제 없이 도입합니다.

#### 월드 구조

두 번째 구역은 작은 공중 플랫폼 3개로 구성됩니다.

```text
플랫폼:
A: 왼쪽 앞
B: 중앙 뒤
C: 오른쪽 앞

표식:
각 플랫폼에는 색·방향·아이콘이 있음.
숫자 좌표는 보조 정보로만 표시.
```

드론이 짧게 말합니다.

```text
“신호는 오른쪽으로 2, 앞으로 1칸!”
```

화면에는 아래처럼 간단히 보입니다.

```text
목표: 드론을 오른쪽 2칸, 앞으로 1칸 이동시키세요.
```

플레이어는 3개의 플랫폼 중 하나를 밟습니다. 플랫폼 선택은 이동 행동이며, 정답 버튼이 아닙니다.

#### 결과 분기

| 선택 | 결과 | 피드백 |
|---|---|---|
| 정답 플랫폼 | 드론이 신호에 도착, 2/3 | “정확해! 신호가 깨어났어.” |
| 좌/우만 맞음 | 드론이 인접 플랫폼에 착륙 | “방향은 맞아. 앞뒤를 한 번 더 확인해 보자.” |
| 완전히 다름 | 드론이 잘못된 플랫폼을 비춤 | “드론이 다른 신호를 찾았어. 빛나는 방향선을 따라가 보자.” |

#### 난이도 조절

```text
첫 시도:
색·방향·거리 아이콘 모두 표시

첫 실패 후:
정답 방향 바닥 타일이 약하게 점멸

두 번째 실패 후:
드론이 정답 플랫폼까지 반쯤 날아가 경로 표시

세 번째 실패 후:
자동으로 가장 가까운 위치에서 재시작
```

통과 실패는 없습니다. 플레이어의 선택 데이터는 내부적으로만 기록해 이후 힌트 강도와 초급 미션 난도에 반영합니다.

### Phase D — 신호 3: 협동 게이트

**목표:** 친구·매칭·NPC 보조 어느 경로에서도 “함께하면 도시가 열린다”를 느끼게 합니다.

#### 기본 퍼즐

```text
오브젝트:
- 좌측 Prism Switch
- 우측 Prism Switch
- 중앙 게이트 에너지 코어

조건:
두 스위치가 3초 이내에 활성화되면 신호 3 완성
```

#### 3개 실행 모드

| 상황 | 시스템 동작 | 플레이어 경험 |
|---|---|---|
| 친구가 인근에 있음 | 친구에게 다른 스위치 역할 제안 | 자연스러운 2인 협동 |
| 혼자임 | 라인 드론이 반대편 스위치로 이동 | 혼자도 즉시 진행 |
| 자동 매칭을 선택 | 최대 10초 매칭 후 미성공 시 드론 전환 | 기다림 없는 협동 기회 |

#### 친구와 플레이할 때

```text
플레이어:
좌측 스위치로 이동

친구:
우측 스위치로 이동

UI:
[나: 준비됨]  [친구: 이동 중]
```

두 스위치에 올라서면 3초 카운트다운이 시작됩니다.

```text
3… 2… 1…
신호 연결!
```

서버 판정은 실제 동시 입력 대신 **3초 허용 창**을 둡니다. 네트워크 지연과 어린이의 조작 속도를 고려한 설계입니다.

#### 혼자 플레이할 때

```text
루미:
“라인 드론이 반대쪽 신호를 맡을게!”

플레이어:
왼쪽 스위치로 이동

라인 드론:
오른쪽 스위치 활성화

결과:
같은 게이트 개방, 같은 핵심 보상
```

친구 협동 보너스는 시각적 효과와 소규모 팀 신뢰도 포인트 정도로만 둡니다. 핵심 보상·자격·지역 해금을 친구가 있다는 이유로 차등 지급하지 않습니다.

#### 중도 이탈 처리

```text
친구가 미션 중 나감:
- 2초 내 라인 드론 생성
- 팀원 이름 대신 “신호 보조 드론 연결 중”
- 진행도 유지
- 재시작 강제 없음

친구가 재접속:
- 관전자 또는 다음 구간부터 재합류
- 이미 지급된 보상은 중복 지급 금지
```

#### 협동 실패 피드백

```text
나쁜 문구:
“팀원이 실패했습니다.”

좋은 문구:
“두 신호가 잠깐 어긋났어요.
같은 시간에 빛나면 게이트가 열립니다.”
```

## 5. 게이트 개방과 보상

### 연출

신호 3/3이 되면 화면 전체 UI를 덮지 않습니다. 월드가 보이는 상태에서 아래 변화가 순서대로 일어납니다.

```text
1. 게이트의 세 링이 점등
2. 한강 방향의 빛이 게이트로 모임
3. 단청 패턴이 링 위에 나타남
4. 게이트가 회전하며 열림
5. 수학마을의 열차·궁전·탑이 보임
6. 라인 드론이 포털 너머를 가리킴
```

### 보상 카드

```text
┌────────────────────────────────────────┐
│            탐험 카드 발급!              │
│                                        │
│       시민 견습생 · Level 1             │
│                                        │
│  새 능력: 도시 이동 부스터              │
│  다음: Metro District 탐험              │
│                                        │
│             [첫 구역으로 가기]          │
└────────────────────────────────────────┘
```

#### 보상 설계 원칙

- 코인 숫자보다 새 행동·새 지역을 우선
- 전원에게 동일한 핵심 보상
- 친구 협동 시에는 “팀 신뢰도 +1” 같은 부가 보상
- 결제·상점·랜덤 박스·출석 보상 노출 금지
- 시민 견습생은 현실 신분이 아닌 게임 내 명예 타이틀이라고 설정 화면에 명시

## 6. 첫 지역 선택

게이트를 열자마자 플레이어에게 5개 지역을 고르게 하면 길을 잃습니다. 처음에는 **추천 경로 하나 + 나중에 열릴 선택지 둘**만 보여 줍니다.

```text
추천 지역:
Metro District

이유:
- 첫 자격: Metro Pathfinder
- 플레이 시간: 약 8분
- 친구와 협동 가능
- 이동 부스터를 바로 사용할 수 있음

나중에 열림:
Pattern Palace
Han River Dock
```

표시:

```text
다음 탐험:
[추천] Metro District — 멈춘 열차 노선을 복구하세요.
보상: Metro Pathfinder 견습 배지
[Metro District로 가기]
```

5초 동안 입력이 없으면 라인 드론이 Metro District 방향으로 날아가고, 지도에 해당 위치만 밝아집니다.

### MVP 합격 기준 예시

초기에는 업계 평균 숫자를 그대로 목표로 고정하기보다, 첫 버전의 기준선을 만든 뒤 개선 폭을 보는 것이 낫습니다. 다만 출시 후보를 막을 최소 안전선은 둘 수 있습니다.

| 항목 | 출시 후보 최소선 | 경고 조건 |
|---|---:|---|
| 첫 입력 발생 | 90% 이상 | 80% 미만 |
| 신호 1 도달 | 85% 이상 | 70% 미만 |
| 신호 2 완료 | 75% 이상 | 60% 미만 |
| 게이트 개방 | 70% 이상 | 55% 미만 |
| 첫 지역 진입 | 60% 이상 | 45% 미만 |
| 튜토리얼 평균 시간 | 3~5분 | 7분 초과 |
| 매칭 대기 중앙값 | 10초 이하 | 15초 초과 |
| NPC 대체 후 완주율 | 친구 협동 대비 큰 하락 없음 | 15%p 이상 하락 |
| D1 재방문 | 초기 기준선 대비 상승 | 튜토리얼 변경 후 하락 |

Roblox는 FTUE에서 목표 달성률과 Day 1 유지율을 보고, 온보딩 퍼널의 어느 단계에서 이탈이 발생하는지 분석해 개선할 것을 안내합니다. [create.roblox](https://create.roblox.com/docs/production/game-design/onboarding)

## 8. A/B 테스트 백로그

### 실험 A — 첫 이동 안내

## 9. 자동 QA Harness

### 기능 테스트

```text
T01: 신규 플레이어 스폰 → 게이트가 3초 이내 보임
T02: 5초 미입력 → 이동 힌트가 정확히 한 번 나타남
T03: 신호 1 상호작용 → 진행도 1/3, 중복 카운트 없음
T04: 신호 2 정답 선택 → 2/3으로 전이
T05: 신호 2 오답 2회 → 힌트 강화, 진행 불가 상태 없음
T06: 혼자 플레이 → NPC 드론이 신호 3 보조
T07: 2인 플레이 → 3초 허용 창 안에서 협동 성공
T08: 협동 중 1인 이탈 → NPC 대체, 체크포인트 유지
T09: 두 명이 동시에 완료 요청 → 양측 보상 정확히 1회
T10: 재접속 → 진행 상태 복구, 보상 중복 없음
T11: 게이트 개방 → 탐험 카드와 Metro District 포털 노출
T12: 튜토리얼 완료 → 이후 입장 시 반복 강제 없음
```

### 모바일·UI 테스트

```text
U01: 360×800 세로 화면에서 목표·진행도·상호작용 버튼이 보임
U02: 기본 조이스틱·점프 버튼과 겹치는 UI 없음
U03: 노치·홈 인디케이터 영역에 핵심 텍스트 없음
U04: 가로 전환 시 UI 재배치 및 버튼 기능 유지
U05: 긴 언어 번역에서도 버튼·카드·진행도가 잘리지 않음
U06: 색만으로 방향·역할·정답을 판단하지 않아도 됨
U07: 터치·키보드·게임패드로 모두 완주 가능
U08: 저사양 프로필에서 파티클·조명 감소 후에도 목적지가 보임
```

### 멀티플레이·보안 테스트

```text
M01: 클라이언트가 signal_completed 요청을 임의 전송해도 서버가 거부
M02: 보상 RemoteEvent 반복 호출 시 중복 지급 없음
M03: 다른 플레이어의 신호 상태를 임의 변경할 수 없음
M04: 친구 이탈·재입장 시 팀 상태가 깨지지 않음
M05: 매칭 대기 10초 초과 시 자동 NPC 전환
M06: 신호 동시 판정은 서버 시간 기준으로만 처리
M07: 팀원 비활동 상태가 장시간이어도 다른 플레이어가 막히지 않음
```

Studio의 테스트 자동화와 멀티플레이 테스트 기능을 이용하면, 위 시나리오를 반복 실행해 서버 측 성공·실패 결과를 자동 판정하도록 구성할 수 있습니다. [create.roblox](https://create.roblox.com/docs/reference/engine/classes/StudioTestService)

## 최종 기획 원칙

수학마을 탐험 게이트는 다음을 만족해야 합니다.

```text
첫 15초:
목표가 보인다.

첫 60초:
움직이고, 상호작용하고, 세계가 반응한다.

첫 2분:
수학적 판단을 행동으로 경험한다.

첫 3분:
혼자 또는 친구와 협동 성공을 경험한다.

첫 4분:
게이트가 열리며 도시가 바뀐다.

첫 5분:
새 능력·새 지역·새 자격이라는 다음 목표가 보인다.
```

최종적으로 플레이어에게 남겨야 할 감정은 다음입니다.

> “나는 수학 문제를 풀어서 통과한 게 아니다.  
> 친구와 신호를 맞추고 Neo Seoul의 수학마을을 열었다.”
