Roblox에서 동적 피드백 시스템은 **서버가 검증된 게임 결과를 결정하고, 클라이언트 UI가 그 결과를 즉시·짧게·행동 가능하게 보여 주는 구조**로 구현하면 됩니다. 핵심은 “정답/오답 팝업”이 아니라 `관찰 → 원인 단서 → 다음 행동 → 즉시 재시도` 상태를 데이터로 보내고, UI가 상태별로 렌더링하게 만드는 것입니다.

Roblox에서는 서버-클라이언트 간 단방향 상태 알림에 `RemoteEvent`를 쓰는 것이 적합하며, UI 상태 전환은 `ModuleScript` 기반 컨트롤러와 `TweenService`로 관리하는 방식이 공식 UI 가이드와 잘 맞습니다. [create.roblox](https://create.roblox.com/docs/scripting/events/remote)

## 구조

```text
플레이어 행동
  ↓
클라이언트: 상호작용 의도 전송
  ↓
서버: 거리·순서·상태·수학 규칙 검증
  ↓
서버: 결과/힌트 단계/다음 행동 결정
  ↓
RemoteEvent: 해당 플레이어에게 FeedbackPayload 전송
  ↓
클라이언트 FeedbackController:
- UI 카드 표시
- 월드 강조 효과
- 사운드/햅틱
- Tween 애니메이션
- 재시도 버튼 연결
  ↓
플레이어가 조절·재시도
```

### 원칙

- **클라이언트는 의도만 보냅니다.** 예: “경사 2를 선택했다.”
- **서버만 결과를 확정합니다.** 예: “목표보다 낮음, 힌트 레벨 1.”
- 클라이언트가 `success = true`, `reward = 100` 같은 결과를 보내게 만들면 조작될 수 있습니다.
- UI는 서버 상태를 “표현”할 뿐, 자격증·보상·시민권·진도 변경을 결정하지 않습니다.
- `RemoteFunction`은 응답을 기다리는 동기 호출이라 UI 갱신용으로 남용하지 말고, 대부분의 피드백은 `RemoteEvent`로 비동기 처리합니다. Roblox도 GUI 업데이트처럼 응답을 기다릴 필요 없는 경우 `RemoteEvent`를 권장합니다. [create.roblox](https://create.roblox.com/docs/scripting/events/remote)

## 데이터 계약

먼저 모든 피드백을 공통 데이터 형태로 정의하세요. 이게 Intent → Graph → Harness 구조의 UI 경계입니다.

```lua
-- ReplicatedStorage/Shared/FeedbackTypes.lua
export type FeedbackPayload = {
    eventId: string,
    kind: "success" | "adjust" | "hint" | "team" | "warning",
    severity: 0 | 1 | 2 | 3,

    bodyKey: string,

        id: string,
        labelKey: string,
        targetId: string?,

        targetId: string?,

        effect: string?,
```

서버가 실제 한국어·영어 문장을 직접 보내기보다 `titleKey`, `bodyKey`, `labelKey` 같은 **현지화 키**를 보내는 편이 좋습니다.

```lua
{
```

Roblox의 `LocalizationService`와 `LocalizationTable`은 UI 문자열의 자동 대체를 지원합니다. 동적 문장도 지역화 테이블의 파라미터를 이용해 처리할 수 있으므로, “목표보다 1층 낮게 도착했어”처럼 숫자만 바뀌는 문구도 키 기반으로 관리하세요. [create.roblox](https://create.roblox.com/docs/reference/engine/classes/LocalizationService)

## 서버 구현

### 1. 서버는 행동을 검증한다

예를 들어 플레이어가 “경사 조절 레버”에서 값을 선택하면, 클라이언트는 선택값과 대상 ID만 보냅니다.

```lua
-- Client → Server
SubmitMathAction:FireServer({
    action = "set_slope",
    targetId = "SlopeConsole_02",
    slope = 1,
})
```

서버는 다음을 검증합니다.

```text
- 플레이어가 실제 레버 근처에 있는가
- 현재 퀘스트 상태에서 이 레버를 조작할 수 있는가
- slope 값이 허용 범위인가
- 이미 완료된 미션을 재요청하는가
- 호출 빈도가 비정상적으로 빠른가
- 팀 미션이라면 역할·시간창 조건을 만족하는가
```

### 2. 서버가 결과와 피드백 단계를 계산한다

```lua
-- ServerScriptService/FeedbackService.lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local FeedbackService = {}

        payload = {
            eventId = "slope_too_low",

            severity = 1,
            titleKey = "feedback.slope.too_low.title",
            bodyKey = "feedback.slope.too_low.body",
```

### 3. 힌트는 서버 상태로 관리한다

같은 플레이어가 같은 오개념 유형에서 반복적으로 막히면, 서버가 힌트 레벨을 올립니다.

```lua
-- 개념 예시: 실제 저장 구조는 DataStore/세션 서비스로 분리
local attemptState = {}

local function getHintLevel(player, skillId)
    local userId = player.UserId
    attemptState[userId] = attemptState[userId] or {}
    attemptState[userId][skillId] = attemptState[userId][skillId] or 0
    return attemptState[userId][skillId]
end

local function recordAttempt(player, skillId, correct)
    local userId = player.UserId
    attemptState[userId] = attemptState[userId] or {}
    attemptState[userId][skillId] = attemptState[userId][skillId] or 0

    if correct then
        attemptState[userId][skillId] = 0
        return 0
    end

    attemptState[userId][skillId] += 1
    return math.min(attemptState[userId][skillId], 3)
end
```

권장 단계는 다음과 같습니다.

```text
힌트 0: 결과만 보여 주기
힌트 1: 목표와 현재 결과 비교
힌트 2: 확인할 변수 하나 강조
힌트 3: 조절할 오브젝트·방향 제시
힌트 4: NPC/드론의 부분 시범
```

이 데이터는 플레이어에게 “약점”으로 공개하지 않습니다. 내부적으로 다음 미션의 UI 단서·선택지 수·NPC 도움 수준을 바꾸는 데만 사용하세요.

## 클라이언트 UI 구현

### 1. FeedbackController를 상태 기반으로 만든다

UI를 여러 스크립트가 직접 켜고 끄게 하면, 이벤트가 연속으로 오거나 협동 미션이 겹칠 때 꼬입니다. 하나의 Controller가 상태를 단일하게 관리해야 합니다.

```lua
-- StarterPlayerScripts/FeedbackController.lua
local TweenService = game:GetService("TweenService")
local Players = game:GetService("Players")

local FeedbackController = {}
FeedbackController.__index = FeedbackController

function FeedbackController.new(gui)
    local self = setmetatable({}, FeedbackController)

    self.gui = gui
    self.card = gui.FeedbackCard
    self.icon = self.card.Icon
    self.title = self.card.Title
    self.body = self.card.Body
    self.actionButton = self.card.ActionButton
    self.progressFill = self.card.Progress.Fill

    self.currentToken = 0
    self.currentPayload = nil

    self.card.Visible = false
    self.card.GroupTransparency = 1

    return self
end

function FeedbackController:_styleFor(kind)
    local styles = {
        success = {
            color = Color3.fromRGB(38, 218, 181),
            icon = "rbxassetid://SUCCESS_ICON_ID",
        },
        adjust = {
            color = Color3.fromRGB(255, 201, 74),
            icon = "rbxassetid://ADJUST_ICON_ID",
        },
        hint = {
            color = Color3.fromRGB(169, 121, 255),
            icon = "rbxassetid://HINT_ICON_ID",
        },
        team = {
            color = Color3.fromRGB(91, 180, 255),
            icon = "rbxassetid://TEAM_ICON_ID",
        },
        warning = {
            color = Color3.fromRGB(255, 128, 128),
            icon = "rbxassetid://WARNING_ICON_ID",
        },
    }

    return styles[kind] or styles.hint
end

function FeedbackController:_tween(instance, properties, duration)
    local tween = TweenService:Create(
        instance,
        TweenInfo.new(duration, Enum.EasingStyle.Quad, Enum.EasingDirection.Out),
        properties
    )
    tween:Play()
    return tween
end

function FeedbackController:show(payload, resolveText, onAction)
    self.currentToken += 1
    local token = self.currentToken
    self.currentPayload = payload

    local style = self:_styleFor(payload.kind)

    self.title.Text = resolveText(payload.titleKey)
    self.body.Text = resolveText(payload.bodyKey)
    self.icon.Image = style.icon
    self.card.Accent.BackgroundColor3 = style.color

    if payload.progress then
        local ratio = payload.progress.current / payload.progress.total
        self.progressFill.Size = UDim2.fromScale(ratio, 1)
        self.card.Progress.Visible = true
    else
        self.card.Progress.Visible = false
    end

    if payload.action then
        self.actionButton.Visible = true
        self.actionButton.Text = resolveText(payload.action.labelKey)
        self.actionButton.Activated:Once(function()
            if token ~= self.currentToken then
                return
            end
            onAction(payload.action, payload)
        end)
    else
        self.actionButton.Visible = false
    end

    self.card.Visible = true
    self.card.Position = UDim2.fromScale(0.5, 1.08)
    self.card.GroupTransparency = 1

    self:_tween(self.card, {
        Position = UDim2.fromScale(0.5, 0.77),
        GroupTransparency = 0,
    }, 0.22)

    local duration = payload.duration or 3.5
    task.delay(duration, function()
        if token == self.currentToken and not payload.action then
            self:hide()
        end
    end)
end

function FeedbackController:hide()
    self.currentToken += 1

    local tween = self:_tween(self.card, {
        Position = UDim2.fromScale(0.5, 1.08),
        GroupTransparency = 1,
    }, 0.18)

    tween.Completed:Once(function()
        self.card.Visible = false
    end)
end

return FeedbackController
```

`TweenService`는 GUI 객체의 위치·크기·투명도·회전 같은 속성을 부드럽게 보간하는 데 쓰이며, 화면 크기별 반응성을 위해 픽셀 고정값보다 `UDim2.fromScale()` 중심 배치를 사용하는 것이 좋습니다. [create.roblox](https://create.roblox.com/docs/reference/engine/classes/TweenService)

### 2. LocalScript에서 RemoteEvent를 구독한다

```lua
-- StarterGui/FeedbackGui/FeedbackClient.client.lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local FeedbackEvent = ReplicatedStorage.Remotes.FeedbackEvent
local RequestFeedbackAction = ReplicatedStorage.Remotes.RequestFeedbackAction

local FeedbackController = require(
    game.Players.LocalPlayer.PlayerScripts.FeedbackController
)

local gui = script.Parent
local controller = FeedbackController.new(gui)

local function resolveText(key)
    -- 실제 구현에서는 LocalizationTable 또는 키→문구 모듈 사용
    local dictionary = {
        ["feedback.slope.too_low.title"] = "목표보다 낮게 도착했어",
        ["feedback.slope.too_low.body"] = "경사나 출발 높이를 바꿔 볼까?",
        ["feedback.slope.success.title"] = "신호가 연결됐어!",
        ["feedback.slope.success.body"] = "출발 위치와 경사를 함께 확인했어.",
        ["action.adjust_slope"] = "경사 조절하기",
        ["action.continue"] = "계속하기",
    }

    return dictionary[key] or key
end

local function onAction(action, payload)
    RequestFeedbackAction:FireServer({
        actionId = action.id,
        targetId = action.targetId,
        sourceEventId = payload.eventId,
    })
end

FeedbackEvent.OnClientEvent:Connect(function(payload)
    controller:show(payload, resolveText, onAction)
end)
```

UI 업데이트처럼 서버에서 클라이언트로 상태를 푸시하는 경우 `RemoteEvent:FireClient()`와 클라이언트의 `OnClientEvent` 조합이 맞습니다. `RemoteEvent`는 비동기 단방향 통신이므로 UI 갱신 과정에서 서버 응답을 기다려 게임 흐름을 멈추지 않습니다. [create.roblox](https://create.roblox.com/docs/scripting/events/remote)

## 액션 버튼은 ‘UI 버튼’이 아니라 월드 행동으로

피드백 카드의 버튼을 누르면 정답이나 보상을 주지 말고, 플레이어가 **다음 행동을 할 수 있는 월드 상태**를 열어 주세요.

```text
[경사 조절하기]
→ 카메라가 경사 콘솔을 부드럽게 가리킴
→ 콘솔이 청록/노랑으로 점멸
→ 조작 가능한 레버가 활성화
→ 플레이어가 실제 값을 바꿈
→ 서버가 다시 검증
```

서버 예시입니다.

```lua
-- ServerScriptService/GateService.server.lua
RequestFeedbackAction.OnServerEvent:Connect(function(player, request)
    if request.actionId ~= "adjust_slope" then
        return
    end

    if not isValidFeedbackAction(player, request) then
        return
    end

    local console = workspace.MathVillage.SlopeConsole_02
    if not isNear(player, console, 20) then
        return
    end

    enableSlopeConsoleFor(player, console)
    FeedbackEvent:FireClient(player, {
        eventId = "slope_console_ready",
        kind = "hint",
        severity = 0,
        titleKey = "feedback.slope.console_ready.title",
        bodyKey = "feedback.slope.console_ready.body",
        visual = {
            targetId = "SlopeConsole_02",
            color = "yellow",
            effect = "pulse",
        },
        duration = 2.5,
    })
end)
```

중요한 점은 `RequestFeedbackAction`도 신뢰하지 않는 것입니다. 클라이언트가 임의 `targetId`를 보내도 서버가 현재 퀘스트 상태, 거리, 행동 순서, 호출 빈도를 검증해야 합니다.

## 월드 피드백 연결

UI 카드만 나오면 공부 앱처럼 느껴질 수 있습니다. `visual.targetId`를 이용해 월드 효과를 동시에 실행하세요.

```lua
-- StarterPlayerScripts/WorldFeedbackController.lua
local TweenService = game:GetService("TweenService")

local WorldFeedbackController = {}

function WorldFeedbackController:play(visual)
    if not visual or not visual.targetId then
        return
    end

    local target = workspace:FindFirstChild(visual.targetId, true)
    if not target then
        return
    end

    if visual.effect == "pulse" then
        local highlight = target:FindFirstChildOfClass("Highlight")
        if highlight then
            highlight.Enabled = true
            local tween = TweenService:Create(
                highlight,
                TweenInfo.new(0.35, Enum.EasingStyle.Sine, Enum.EasingDirection.InOut, 3, true),
                { FillTransparency = 0.35 }
            )
            tween:Play()
        end
    elseif visual.effect == "activate" then
        local light = target:FindFirstChildWhichIsA("PointLight", true)
        if light then
            TweenService:Create(
                light,
                TweenInfo.new(0.25, Enum.EasingStyle.Quad, Enum.EasingDirection.Out),
                { Brightness = 4 }
            ):Play()
        end
    end
end

return WorldFeedbackController
```

그리고 UI 이벤트 수신 시 함께 호출합니다.

```lua
FeedbackEvent.OnClientEvent:Connect(function(payload)
    WorldFeedbackController:play(payload.visual)
    controller:show(payload, resolveText, onAction)
end)
```

| 보상 | 도시 조명·포털 개방 | 새 능력·다음 지역 카드 |

## ProximityPrompt와 연결

수학마을 게이트의 패널·레버·드론 콘솔에는 `ProximityPrompt`를 붙이세요. 플레이어가 가까워졌을 때만 입력 UI가 나타나므로 모바일·PC·게임패드에서 상호작용 방식을 통일하기 좋습니다. `ProximityPromptService`로 프롬프트 표시·트리거를 한 곳에서 수집할 수도 있습니다. [create.roblox](https://create.roblox.com/docs/reference/engine/classes/ProximityPrompt)

```lua
-- ServerScriptService/PromptRouter.server.lua
local ProximityPromptService = game:GetService("ProximityPromptService")

ProximityPromptService.PromptTriggered:Connect(function(prompt, player)
    if prompt.Name == "SignalOnePrompt" then
        activateSignalOne(player)
    elseif prompt.Name == "SlopeConsolePrompt" then
        openSlopeConsoleFor(player)
    end
end)
```

단, `PromptTriggered`가 발생했다고 해서 모든 보상을 바로 주지 마세요. 퀘스트 상태와 거리, 이미 완료 여부를 서버에서 다시 확인해야 합니다.

## 피드백 큐와 우선순위

실전에서는 피드백이 겹칩니다.

```text
신호 2 실패
+ 힌트 단계 상승
+ 팀원이 입장
+ 네트워크 재연결
+ 목표 업데이트
```

모두 팝업으로 띄우면 UX가 무너집니다. 이벤트를 우선순위 큐로 처리하세요.

```text
우선순위 1: 안전/연결 문제
우선순위 2: 즉시 행동이 필요한 피드백
우선순위 3: 미션 진행 업데이트
우선순위 4: 성공·보상
우선순위 5: 정보성 팁
```

| 이벤트 | UI 방식 | 처리 |
|---|---|---|
| 재접속/저장 실패 | 고정 배너 | 다른 카드보다 우선 |
| “경사 조절하기” | 행동 카드 | 사용자가 처리할 때까지 유지 |
| 진행도 2/3 | HUD 미세 애니메이션 | 팝업 없음 |
| 팀원 준비 | 월드 아이콘 + HUD | 팝업 없음 |
| 배지 획득 | 짧은 보상 카드 | 행동 카드 뒤에 큐잉 |
| 팁 | 작은 토스트 | 전투/미션 중 억제 |

### 최소 큐 구현

```lua
local FeedbackQueue = {}
FeedbackQueue.items = {}
FeedbackQueue.isShowing = false

function FeedbackQueue:push(payload)
    table.insert(self.items, payload)
    table.sort(self.items, function(a, b)
        return (a.priority or 5) < (b.priority or 5)
    end)
    self:next()
end

function FeedbackQueue:next()
    if self.isShowing or #self.items == 0 then
        return
    end

    self.isShowing = true
    local payload = table.remove(self.items, 1)

    controller:show(payload, resolveText, function(action, sourcePayload)
        onAction(action, sourcePayload)
        self.isShowing = false
        self:next()
    end)

    if not payload.action then
        task.delay(payload.duration or 3, function()
            self.isShowing = false
            self:next()
        end)
    end
end
```

실제 구현에서는 `controller:hide()` 완료 시점과 연결해 중복 타이머, 버튼 클릭, 새 이벤트 도착 시 이전 카드 취소를 더 엄격히 처리하세요.

## 접근성과 다국어

동적 피드백은 글로벌 아동 게임에서 특히 UI가 깨지기 쉽습니다.

### 필수 규칙

- 색만으로 성공·조정·위험을 구분하지 않기
- 아이콘 + 색 + 텍스트 + 월드 변화 병행
- 카드 본문은 1~2문장으로 제한
- 버튼은 기본 1개만
- 긴 독일어·러시아어·포르투갈어 번역에서 자동 줄바꿈과 버튼 확장 지원
- 아랍어 등 RTL 언어는 정렬·아이콘 위치를 별도 검증
- 효과음·햅틱을 꺼도 피드백을 이해할 수 있게 만들기
- 화면 투명도·글자 크기·대비 설정 존중
- 작은 모바일에서 기본 조이스틱·점프 버튼을 덮지 않기

Roblox의 `LocalizationService`는 로컬라이제이션 테이블을 통한 UI 텍스트 자동 대체를 처리하며, 동적 콘텐츠는 파라미터가 포함된 번역 키로 관리할 수 있습니다. [create.roblox](https://create.roblox.com/docs/reference/engine/classes/LocalizationService)

## 자동 QA Harness

동적 UI는 정적 스크린샷만으로 부족합니다. 상태 전이 테스트를 만드세요.

```text
D01: 서버가 invalid action을 받으면 FeedbackEvent를 보내지 않는다.
D02: valid action 후 1초 이내 정확한 FeedbackPayload가 도착한다.
D03: action 카드에는 기본 행동 버튼이 정확히 하나다.
D04: 새 피드백이 오면 이전 자동닫힘 타이머가 새 카드에 영향을 주지 않는다.
D05: 성공 피드백은 progress HUD만 갱신하고 불필요한 팝업을 남발하지 않는다.
D06: 3회 반복 실패 시 hintLevel이 상승한다.
D07: 성공 후 같은 skill의 hintLevel은 초기화 또는 완화된다.
D08: 협동 실패 문구에 개인 플레이어 이름이나 비난 표현이 없다.
D09: 360×800 화면에서 카드가 조이스틱·점프·상호작용 버튼을 가리지 않는다.
D10: 언어별 최대 길이 문구에서 카드와 버튼이 잘리지 않는다.
D11: action 버튼을 연타해도 서버에서는 한 번만 유효 처리된다.
D12: 재접속 후 퀘스트 상태와 힌트 상태가 일관되게 복구된다.
D13: 보상 이벤트는 서버에서 정확히 한 번만 지급된다.
```

## 구현 순서

처음부터 모든 피드백 유형을 만들지 말고, 다음 순서가 좋습니다.

1. **단일 피드백 카드**  
   성공·조정·힌트 3개 스타일, 텍스트 2줄, 버튼 1개.

2. **서버 검증 + `RemoteEvent`**  
   하나의 좌표/경사 미션에서 결과를 서버가 판단해 UI로 전송.

3. **월드 하이라이트 연결**  
   카드의 `targetId`로 실제 레버·드론·신호 패널을 강조.

4. **힌트 단계 시스템**  
   같은 오류 반복 시 결과 → 비교 → 변수 강조 → 부분 시범 순으로 강화.

5. **피드백 큐**  
   협동·진행·보상 이벤트가 겹칠 때 행동 피드백을 최우선으로 유지.

6. **현지화 및 접근성**  
   키 기반 문구, 동적 파라미터, 작은 화면, 오디오/햅틱 제어.

7. **분석·실험**  
   어떤 피드백이 실제 재시도·성공·다음 지역 진입으로 이어지는지 측정하고, 문구·타이밍·시각 단서를 A/B 테스트합니다.

## 결론

Roblox 동적 피드백 시스템의 정답 구조는 다음입니다.

```text
서버:
검증 · 상태 · 수학 판정 · 힌트 단계 · 보상 권한

RemoteEvent:
검증된 피드백 상태 전달

클라이언트:
짧은 UI · 월드 강조 · 애니메이션 · 사운드 · 다음 행동 유도

플레이어:
즉시 조절 · 재시도 · 결과 확인
```

즉, UI는 “오답 알림 창”이 아니라 **플레이어가 다음 실험을 실행하도록 월드의 조절 장치와 연결해 주는 인터페이스**가 되어야 합니다.
