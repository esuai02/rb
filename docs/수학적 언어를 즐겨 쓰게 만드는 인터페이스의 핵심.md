언어 학습 Roblox 게임의 UI는 “단어장·시험지”가 아니라, \*\*플레이어가 말하고, 듣고, 선택하고, 그 표현 때문에 월드가 바뀌는 인터페이스\*\*여야 합니다. 당신의 게임은 외국어가 아니라 수학적 언어를 일상어처럼 익히게 하는 것이므로, UI도 “용어 암기 UI”가 아니라 \*\*도시 소통 UI\*\*로 설계하는 것이 맞습니다.



핵심 공식은 다음입니다.



```text

상황

→ 플레이어가 표현 선택

→ 월드가 반응

→ 짧은 언어 발견 피드백

→ 다른 상황에서 같은 표현 재사용

```



Roblox UI는 화면 크기·방향·입력 방식에 따라 달라지는 적응형 설계와, 언어별 길이 차이를 견딜 수 있는 현지화 구조를 전제로 해야 합니다. \[create.roblox](https://create.roblox.com/docs/production/publishing/adaptive-design)



\## UI 원칙



\### 1. “배우기”보다 “말하기”



피해야 할 화면입니다.



```text

기울기란?

① 직선이 기울어진 정도

② …

\[정답 제출]

```



권장 화면입니다.



```text

열차가 목표보다 낮게 도착했습니다.



팀에 어떻게 말할까요?



\[조금 더 올라가게]

\[같은 높이로]

\[조금 더 내려가게]

```



플레이어가 일상어를 선택하면 월드가 반응하고, 성공 뒤에만 짧게 이름을 붙입니다.



```text

새 도시 말 발견

기울기 = 길이 얼마나 올라가거나 내려가는지 말하는 방법

```



이렇게 하면 용어가 “외워야 할 정의”가 아니라, \*\*방금 쓴 표현의 이름\*\*이 됩니다.



\### 2. UI는 문장보다 ‘의도’를 보여 준다



글로벌 아동 게임의 언어 인터페이스는 문장이 길수록 실패합니다. 각 표현을 아래 네 요소로 구성하세요.



```text

아이콘 + 짧은 표현 + 월드 미리보기 + 선택 결과

```



예시:



| 표현 | 아이콘 | 월드 미리보기 | 수학 언어 연결 |

|---|---|---|---|

| 더 올라가게 | ↗ | 열차 경로가 위로 기울어짐 | 양의 기울기 |

| 더 내려가게 | ↘ | 열차 경로가 아래로 기울어짐 | 음의 기울기 |

| 같은 높이 | → | 경로가 평평해짐 | 기울기 0 |

| 반반 나누기 | ◐ | 에너지 바가 동일하게 분리 | 1:1 비율 |

| 두 배 보내기 | ×2 | 한쪽 에너지 바가 두 배 | 배수·비율 |

| 오른쪽 두 칸 | →→ | 드론이 가로 방향 이동 | x방향 |

| 위로 한 칸 | ↑ | 드론이 세로 방향 이동 | y방향 |



UI는 수학 용어보다 먼저 \*\*행동의 의미\*\*를 전달해야 합니다.



\### 3. 한 화면에는 한 언어 행동만



학습 게임 UI가 복잡해지는 가장 빠른 길은 표현 선택지, 정의, 힌트, 점수, 지도, 친구 목록을 한 화면에 모두 띄우는 것입니다.



```text

좋은 상태:

지금 필요한 말 1개

→ 선택지 2\~4개

→ 한 번 선택

→ 월드 결과



나쁜 상태:

좌표 + 기울기 + 비율 + 인벤토리 +

퀘스트 + 점수 + 대화 + 친구 목록

```



수학마을 게이트의 첫 위치 신호에서는 오직 다음만 보여야 합니다.



```text

드론에게 위치를 알려 주세요.



\[오른쪽]  \[왼쪽]

\[위로]    \[아래로]

```



선택 뒤에만 다음 단계를 보여 줍니다.



```text

얼마나 멀리 갈까요?



\[한 칸] \[두 칸] \[세 칸]

```



이런 \*\*두 단계 표현 조합 UI\*\*는 초보자에게 선택 부담을 줄이고, 나중에 “오른쪽 2, 위 1”을 하나의 좌표 표현으로 연결하기 좋습니다.



\## 핵심 화면 6개



\### 1. 도시 언어 HUD



게임 플레이 중 늘 떠 있는 화면입니다. 단, HUD는 최소화합니다.



```text

┌─────────────────────────────────────┐

│ 도시 신호 2 / 3                      │

│ 현재 말: 위치                         │

│                                     │

│                    \[탐험 지도책] \[⚙] │

└─────────────────────────────────────┘

```



표시 원칙:



\- 현재 미션 1개

\- 현재 사용 중인 도시 언어 범주 1개

\- 진행도 1개

\- 나머지는 숨김

\- 수학 용어는 처음에는 작거나 보조적으로 표시

\- UI보다 월드 속 신호·경로·NPC가 더 중요



\### 2. 표현 선택 휠



친구와 협동하거나 도시 장치를 조작할 때 사용하는 핵심 UI입니다.



```text

&#x20;                \[더 올라가게]

&#x20;                      ↗



&#x20;\[왼쪽으로] ←      ●      → \[오른쪽으로]



&#x20;                      ↘

&#x20;                \[더 내려가게]

```



초반에는 \*\*일상어 우선\*\*으로 보여 줍니다.



```text

\[더 올라가게]

작게: 기울기 ↑

```



숙련도·반복 사용이 쌓이면 바꿉니다.



```text

\[기울기 ↑]

작게: 더 올라가게

```



하지만 사용자가 수학 용어를 선택하지 않아도 항상 진행할 수 있어야 합니다.



\#### 표현 휠 분류



| 상황 | 초반 표현 | 연결되는 수학 언어 |

|---|---|---|

| 위치 | 오른쪽, 왼쪽, 위, 아래 | 좌표, x/y 방향 |

| 변화 | 더 올라가게, 더 내려가게, 평평하게 | 기울기, 증가/감소 |

| 관계 | 반반, 더 많이, 두 배 | 비율, 부분/전체 |

| 패턴 | 돌리기, 뒤집기, 반복하기 | 회전, 대칭, 규칙 |

| 비교 | 더 가까이, 더 멀리, 같은 크기 | 거리, 비교, 단위 |

| 가능성 | 자주, 가끔, 드물게 | 확률, 경우 |



\### 3. 언어 발견 태그



용어 설명은 게임을 멈추는 팝업이 아니라 2초짜리 작은 태그로만 보여 주세요.



```text

┌──────────────────────────────┐

│ 새 도시 말                    │

│ \[좌표] 위치를 알려 주는 말    │

└──────────────────────────────┘

```



규칙:



\- 화면 중앙을 완전히 가리지 않음

\- 1\~2문장

\- 기본 2초 후 축소

\- “확인” 버튼 없음

\- 다음 행동을 막지 않음

\- 같은 용어를 반복 발견했을 때는 설명 대신 재사용 피드백



```text

\[좌표]를 다른 구역에서도 썼어요.

```



\### 4. 결과 비교 카드



정답/오답 대신 “말과 결과”를 비교합니다.



```text

┌──────────────────────────────────┐

│ 네가 말한 길: 더 올라가게          │

│ 열차 결과: 목표보다 한 층 낮음      │

│                                  │

│ 다음에는 무엇을 바꿔 볼까?          │

│            \[경사 다시 조절하기]    │

└──────────────────────────────────┘

```



이 카드는 행동 버튼 하나만 유지합니다. 버튼은 `정답 보기`가 아니라 `경사 다시 조절하기`, `위치 다시 말하기`, `에너지 나누기`처럼 \*\*다음 행동\*\*을 말해야 합니다.



\### 5. 팀 언어 핑



자유 채팅 없이도 협동할 수 있는 UI입니다.



```text

\[여기로]

\[오른쪽]

\[위로]

\[더 가파르게]

\[반반]

\[준비]

\[도움]

\[다시 해보자]

```



표현을 누르면 팀원 화면에는 다음처럼 보입니다.



```text

민지의 신호:

↗ 더 올라가게

```



그 표현이 수학 언어와 연결되면 작은 보조 라벨을 붙입니다.



```text

↗ 더 올라가게

기울기 ↑

```



이 구조는 언어가 개인의 시험 답안이 아니라 \*\*팀과 세계를 움직이는 실용적 신호\*\*가 되게 합니다.



\### 6. 도시 말 모음: 탐험 지도책



사전이 아니라 수집형 앨범입니다.



```text

City Signal Atlas



위치의 말

\[좌표] ● 발견함

“도시에서 위치를 알려 주는 방법”



변화의 말

\[기울기] ○ 아직 발견하지 않음



관계의 말

\[비율] ● 한강 의뢰에서 사용함



규칙의 말

\[대칭] ○ Pattern Palace에서 발견 가능

```



각 항목을 누르면 정의 시험이 아니라 플레이어가 실제로 경험한 장면을 짧게 재생합니다.



```text

좌표:

드론이 네가 고른 위치로 날아간 장면

“오른쪽 2, 위 1”

```

\## 모바일 우선 규칙



Roblox 언어 학습 게임은 텍스트가 많아지기 쉬우므로, 모바일에서 다음을 강제 규격으로 두는 편이 좋습니다.



| 항목 | 권장 |

|---|---|

| 선택지 수 | 한 번에 2\~4개 |

| 버튼 위치 | 하단 중앙 또는 우측, 기본 조이스틱·점프 버튼 회피 |

| 문장 길이 | 1\~2문장, 각 문장은 짧게 |

| 카드 노출 | 2\~4초, 다음 행동이 필요하면 유지 |

| 글자 크기 | 작은 화면에서도 읽히는 최소 크기 확보 |

| 입력 | 터치·키보드·게임패드 동일 행동 가능 |

| UI 크기 | `Scale` 중심 + `UISizeConstraint` |

| 긴 번역 | 자동 줄바꿈, 버튼 길이 확장 |

| 피드백 | 색 + 아이콘 + 움직임 + 문구 병행 |

| 시야 | 월드 중앙을 팝업으로 오래 가리지 않기 |



Roblox의 적응형 디자인 가이드는 UI가 다양한 화면 크기, 방향, 입력 방식에서 자연스럽게 작동해야 하며, 플랫폼별 입력 힌트와 레이아웃을 고려하라고 권장합니다. \[create.roblox](https://create.roblox.com/docs/production/publishing/adaptive-design)



\## 현지화 설계



언어 학습 게임은 현지화가 단순 번역보다 중요합니다. 특히 수학적 언어를 다루므로, 한국어 원문을 그대로 번역하면 용어의 자연스러운 연결이 깨질 수 있습니다.



\### 문자열 구조



```text

나쁜 방식:

TextLabel.Text = "더 올라가게 (기울기 증가)"



좋은 방식:

키 = language.slope.increase.label

ko-KR = "더 올라가게"

en-US = "Make it rise more"

ja-JP = "もっと上がるように"

```



용어 태그도 별도 키로 관리합니다.



```text

키 = term.slope.name

ko-KR = "기울기"

en-US = "slope"

ja-JP = "傾き"

```



그 다음 UI가 언어별 순서를 조립합니다.



```text

초기:

일상어 표현 + 용어 태그



숙련 후:

용어 + 일상어 보조 설명

```



Roblox의 `LocalizationService`와 LocalizationTable은 경험 내 UI 텍스트의 현지화와 자동 대체를 지원합니다. 동적 문구는 파라미터 기반 키로 관리하면 언어별 문장 구조 차이도 대응하기 좋습니다. \[create.roblox](https://create.roblox.com/docs/reference/engine/classes/LocalizationService)



\## 접근성 규칙



언어를 중심으로 하는 게임일수록 읽기·청각·색각 차이를 고려해야 합니다.



\- 색만으로 방향·정답·팀 역할 전달 금지

\- 표현마다 아이콘·방향선·월드 움직임 병행

\- NPC 대사에는 자막 제공

\- 효과음·음성 없이도 UI로 이해 가능

\- 읽기 속도가 느린 플레이어는 대사를 다시 들을 수 있음

\- 긴 문구 대신 짧은 행동 중심 문장

\- 카메라 흔들림·강한 점멸 끄기 옵션

\- 글자 크기·배경 대비·투명도 설정 반영

\- 시간 제한은 온보딩에서 최소화

\- 음성·자유 입력 없이도 협동 가능



\## AI 생성 규칙



AI가 새 월드·새 표현 UI를 만들 때 아래 제약을 프롬프트/검수 Harness에 넣으세요.



```text

필수:

\- 일상어 표현을 먼저 제시한다.

\- 수학 용어는 행동 뒤에 이름표로 붙인다.

\- 하나의 상호작용에서 새 용어는 최대 하나다.

\- 플레이어가 수학 용어를 몰라도 진행 가능하다.

\- 같은 용어는 최소 세 개의 다른 도시 상황에서 재사용된다.

\- 표현 선택은 월드의 실제 행동을 바꾼다.

\- 용어 사용을 점수·등수·실력 비교로 공개하지 않는다.

\- 실패는 ‘표현 재조정’으로 표시한다.

\- 모든 핵심 상호작용은 모바일에서 한 손/두 엄지로 가능하다.

\- 자유 텍스트 채팅 없이 협동 표현이 가능하다.



금지:

\- 정의를 먼저 보여 주는 플래시카드 UI

\- 객관식 정답 제출을 핵심 루프로 사용

\- “오답/낙제/실패자” 문구

\- 용어를 몰라서 입장 불가

\- 힌트/재시도를 유료로 제한

\- 과도한 팝업·긴 NPC 대화

```



\## 자동 QA 체크리스트



```text

L01: 신규 플레이어가 첫 30초에 수학 용어 정의를 강제로 읽지 않는다.

L02: 한 화면에 표현 선택지가 4개를 넘지 않는다.

L03: 모든 수학 용어에는 행동/아이콘/월드 결과 연결이 있다.

L04: 일상어만 사용해도 핵심 진행이 가능하다.

L05: 용어 이름표는 행동 뒤에만 나타난다.
```
