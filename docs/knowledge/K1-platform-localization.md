## 2. 자동번역 범위

- 지원 언어는 **18개**다 [검증됨 F1]: 아랍어, 중국어 간체, 중국어 번체, 영어, 프랑스어, 독일어, 힌디어, 인도네시아어, 이탈리아어, 일본어, 한국어, 폴란드어, 포르투갈어, 러시아어, 스페인어, 태국어, 터키어, 베트남어.
- 자료는 "16개 언어 체계"라고 했다 **[틀림]** — 공식 문서는 18개를 나열한다.
- 원문 문자열은 게임의 원본 언어로 간주된다 [검증됨 F2]. 할당량을 다 쓰면 어떻게 되는지는 문서에 없다(확인 안 됨).
- 번역 표를 CSV 로 내려받아 사람이 고친 뒤 다시 올릴 수 있다 → 자동번역은 초안, 우선 언어만 사람 교정 [미대조].
- Creator Hub 위치: Audience → Localization 에서 원본 언어·지원 언어 지정, 자동번역·자동 텍스트 캡처 켜기 [미대조].

## 3. 번역과 교육과정 현지화는 다른 일이다

| 목표 | Roblox 기본 기능으로 | 비용 성격 |
|---|---|---|
| 버튼·NPC 대사·퀘스트 문구 번역 | 가능 | 할당량 안에서 무료 |
| 게임 이름·설명·배지·상품 문구 번역 | 가능 | 무료 |
| "초4" 같은 학년을 나라별 학년 체계로 | 부분 가능 | 기획·콘텐츠 비용 |
| 현지 교육과정 단원 순서 | 자동으로는 불가 | 교육 전문가 검수 |
| 수학 용어·표기·난이도 | 자동만으로는 위험 | 현지 검수 |
| 나라마다 같은 학습 효과 보장 | 불가 | 장기 실험·분석 |

한 단원을 다른 시장에 옮길 때 확인할 것: 그 개념을 몇 학년에 배우는가 · 선수지식(비례식·좌표평면·그래프·음수·방정식)이 보장되는가 · 그 학년에 "함수"라는 말을 쓰는가 · `y = mx + b` 같은 표기가 익숙한가 · 계산기 사용과 평가 방식 · 학교·학부모가 기대하는 난이도.

교육 언어 검수 예: "차가 더 가파른 길에서 더 빨리 올라갔으니 기울기가 더 크다" 같은 문장은 좌표축 방향·음수 기울기·속도와 기울기·게임 물리와 그래프를 섞어 오개념을 만들 수 있다. 말투가 아니라 학습 맥락을 다시 써야 한다.

표시 현지화(번역 표로는 안 풀림): 아랍어 오른쪽→왼쪽 UI, 독일어·러시아어 긴 문장의 넘침, 한·중·일 글자 폭·줄바꿈, 숫자·날짜·단위, 화폐·결제 문구, 아동 대상 말투·농담·보상 표현, 국기·지도·역사 요소의 민감성, 나라별 아동 개인정보·광고·채팅·결제 규제. LocalizationTable 은 문자열을 바꿔 줄 뿐 배치 반전·재배치는 UI 설계에서 따로 해야 한다 [미대조].

## 4. 구조 제안 — 공통 엔진 + 시장별 교육팩

```text
하나의 Roblox Experience
  ├─ 공통 로비 Place · 계정/프로필/저장/안전 · 언어 선택·Localization · 분석·Funnel·A/B
  ├─ 시장별 교육팩 (한국 · 영어권 · 일본 · 브라질 …)
  └─ 국가/학년/단원별 월드 Place 또는 동적 인스턴스
```

- 공통 엔진: 이동·월드·멀티플레이, NPC·보상·저장·안전, 모바일 UI 틀, 분석·A/B·자동 QA, 문제 출제·난이도 엔진
- 시장별 교육팩: 학년 체계, 단원 순서, 선수지식 그래프, 용어 사전, 문제 템플릿, 오개념 목록, 예시·맥락, 현지화된 NPC 대사, 교사 검수 기준
- 자료의 추정: 시스템의 80~90% 공유, 10~20% 만 교육팩 [자료 주장]

교육팩 설정 예 (자료 원문, 형식 미확정 — Q1 에서 정한다):

```json
{
  "market": "ko-KR",
  "grade_band": "middle_2",
  "unit_id": "linear_functions",
  "prerequisites": ["coordinate_plane", "proportional_relationships", "signed_numbers"],
  "terminology": {"slope": "기울기", "y_intercept": "y절편"},
  "misconceptions": ["slope_is_always_positive", "larger_number_means_steeper_without_sign", "intercept_is_starting_speed"],
  "ui": {"reading_direction": "ltr", "maximum_dialogue_lines": 3}
}
```

시장 파생 예 [자료 주장, 학년 대응 미검증]: ko-KR 중2 일차함수 → en-US linear relationships → ja-JP 一次関数 → pt-BR funções afins.

## 5. 출시 순서 제안 (intent.md Q4·Q6·Q7 의 근거)

1. 한국어 원본을 먼저 한국 학생 기준으로 검증한다 (재미·학습 목표·모바일 UX·이탈률).
2. 영어를 첫 확장 언어로 둔다. 단 "영어 하나"가 미국·영국·호주·캐나다의 같은 교육과정은 아니다.
3. 자동번역을 켜서 언어권별 유입·플레이 시간·완주율·재방문으로 수요를 탐색한다.
4. 데이터가 나온 상위 2~3개 언어권만 사람 검수를 붙인다.
5. 그 시장의 교육과정 팩을 만든다 (학년·단원·용어·오개념·예시·난이도 규칙).
6. 시장마다 제한적 A/B 로 단원 순서·설명·대사·난이도·보상을 검증한다 (Creator Hub Experiments [미대조]).

비용 판단 4단계 [자료 주장]: 16(→18)개 언어로 보이게 하기 = 거의 무료 · 언어권마다 자연스럽게 읽히게 하기 = AI 초안 + 우선 언어 사람 교정 · 나라별 학교 진도에 맞추기 = 상당한 비용 · 모든 나라 동시 지원 = 다국가 교육 출판·운영 사업.

한 줄 요약 (자료 결론): 게임 엔진은 전 세계 공통으로 만들고, 교과과정·문항·용어·학년·오개념만 국가별 교육팩으로 나눈 뒤, 자동번역으로 수요를 확인한 시장부터 사람 검수와 현지화 비용을 넣는다.
