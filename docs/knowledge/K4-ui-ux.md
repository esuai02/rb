# K4 UI/UX — 공부 화면이 아니라 바로 행동하는 게임 화면

- 출처: 사용자가 2026-10-01 대화에 붙여 넣은 외부 AI 답변("Roblox 교육용 게임 UI/UX"). 원문을 정리했다.
- 성격: 참고 자료다. 지킬 규칙은 `intent.md` INV-8·INV-9, 자동 검수 항목은 Q3 Harness 의 UI 검사 후보다.
- 표기: [미대조] 자료가 Roblox 문서·creator-docs 저장소를 출처로 달았지만 대조 안 함 · [자료 주장] (뜻은 K1 머리말과 같다)
- 연결: intent.md INV-8·INV-9·INV-10, Q3·Q4, K2(게이트)·K5(온보딩)

한 줄 기준: **화면에는 지금 필요한 행동 하나만 보이고, 수학은 그 행동을 더 잘하기 위한 도구로만 느껴져야 한다.**

## 1. 핵심 원칙

1. **첫 화면에는 행동 하나만.** 시작하기·상점·인벤토리·출석·친구·설정·캐릭터·퀘스트·공지·이벤트·언어를 한꺼번에 보이지 않는다. 좋은 첫 화면은 `[수학마을 게이트로 가기]` 하나다. 첫 30초에는 현재 목표 1개 · 이동 방향 1개 · 필요한 조작 1개 · 바로 받을 보상 1개만 보인다. 메뉴·상점·컬렉션·설정은 첫 성공 뒤에 연다.
2. **HUD 는 세 묶음 이하.** 좌상단 현재 미션 목표 · 상단 중앙 팀 진행도 또는 타이머 · 우상단 일시정지/설정. 자격증·코인·인벤토리·지도·시즌 보상·업적·친구 목록은 필요할 때 여는 패널로 숨긴다.
3. **기본 터치 영역을 비운다.** 모바일 기본 이동 조이스틱은 좌하단, 점프 버튼은 우하단이다. 중요한 정보나 커스텀 버튼을 그 영역에 겹치지 않는다. 액션 버튼은 기본 조작 주변의 엄지가 닿는 곳에 둔다 [미대조: creator-docs `ui/position-and-size.md`].
4. **수학은 UI 보다 월드에.** 팝업 객관식("y = 2x + 1 의 기울기는? ①1 ②2 ③3 ④4") 대신 월드 안에서 고르고·보고·실행한다:
   ```text
   두 정거장이 빛난다 → 경사 부품 3개 중 하나를 고른다 → 팀원이 열차를 운행한다
   → 열차가 너무 높은/낮은 곳에 도착한다 → "출발 높이와 경사를 함께 조절해야 해" → 바로 부품을 바꿔 본다
   ```
   UI 는 답안지가 아니라 **도구 패널**이다: 경사 조절 레버 · 노선 지도 · 에너지 게이지 · 드론 경로 표시 · 패턴 조각 회전 버튼 · 팀원 위치·역할 핑.
5. 상호작용은 대상 가까이 갔을 때만 뜨는 `ProximityPrompt` 를 쓴다 [미대조].

## 2. 화면 배치

```text
┌─────────────────────────────────────────┐
│ [미션] 게이트 신호 2/3 복구              │
│                    [팀 에너지 █████░]   │
│              월드와 목표물               │
│ [작은 지도]                  [상호작용] │
│ [이동 조이스틱]               [점프]    │
└─────────────────────────────────────────┘
```

| 위치 | 넣을 것 | 이유 |
|---|---|---|
| 좌상단 | 한 줄 현재 목표 | 가장 빨리 확인할 정보 |
| 상단 중앙 | 팀 진행도·보스/이벤트 상태 | 팀이 같은 상황을 공유 |
| 우상단 | 설정·일시정지 | 자주 누르지 않음 |
| 하단 중앙 또는 우측 | 문 열기·수리·선택 같은 맥락 행동 | 이동·점프를 방해하지 않음 |
| 좌하단 | 기본 이동 조이스틱만 | Roblox 기본 터치 영역 |
| 우하단 | 기본 점프 + 핵심 능력 하나 | 엄지 도달 범위 |
| 월드 안 | 목적지 빔·방향 화살표·거리·NPC 표식 | 메뉴로 화면을 가리지 않음 |

**미션 카드** (2~3초): 제목은 역할·행동 중심("교통 관제", "드론 구조", "패턴 복구") · 설명 한 문장 · 보상 한 줄 · 버튼 하나 · 아이콘 + 짧은 문장 · "함수 단원 3번 문제" 같은 교과서 표현 금지.

**시민권·자격증 UI** 는 성적표가 아니라 도시 탐험 앨범: 빈 배지는 회색 실루엣 · 새 배지는 짧은 애니메이션 · 획득 시 "할 수 있게 된 행동"을 먼저 보여 줌 · 진행률은 보이되 결제·랜덤과 분리 · 실패는 "미획득"이 아니라 "다음 탐험에서 시도 가능".

```text
서울 사이버 시민 수첩
[✓] Metro Pathfinder   [✓] Pattern Architect
[○] Han River Rescuer  [○] Signal Keeper
다음 목표: 협동 도시 복구 2회 완료
```

## 3. 모바일 우선 기술 원칙 [미대조: Roblox Adaptive Design·UI 문서]

| 항목 | 권장 구현 |
|---|---|
| 크기 | `Offset` 고정값만 쓰지 말고 `Scale` 중심 |
| 기준점 | 위치에 맞게 `AnchorPoint` |
| 레이아웃 | `UIListLayout` · `UIGridLayout` · `UIPadding` |
| 비율 | 중요한 카드·아이콘에 `UIAspectRatioConstraint` |
| 최소/최대 | `UISizeConstraint` |
| 안전영역 | `ScreenInsets` 로 노치·홈 인디케이터 회피 |
| 텍스트 | 자동 줄바꿈, `TextScaled` 남용 금지, 실제 소형 폰 확인 |
| 방향 | 세로/가로에서 카드·버튼 재배치 |
| 색상 | 색만으로 정답·위험·역할 구분 금지 |
| 입력 | 터치·키보드·게임패드 각각에서 주요 행동 가능 |
| 포커스 | 게임패드 선택 순서와 포커스 표시를 명시 설계 |
| 접근성 | 글자 크기·투명도·대비 사용자 설정 존중 (`GuiService.PreferredTransparency`) |

기기 에뮬레이터로 iPhone X, Samsung Galaxy A51 같은 화면을 미리 본다 [미대조].

**텍스트 규칙**: 한 화면 2~3줄 · 한 문장에 행동 하나 · 수학 용어는 처음 나올 때 아이콘·행동과 연결 · 한글·영문·독일어·러시아어 길이가 달라도 카드가 깨지지 않게 · 버튼 너비 고정 금지 · 정답/오답을 색만으로 표시하지 않고 ✓·✕·화살표·진동/소리·월드 반응을 함께 · "오답·실패·낙제" 대신 "다른 경로를 시험해 보자" 같은 재도전 언어.

## 4. 협동 UX — 대화창이 아니라 상황 공유 장치

```text
팀 목표: 전력 노드 3개 연결
민지: 지도 확인 중 · Alex: 드론 운반 중 · Ravi: 스위치 대기 중
[신호 필요!]  [도움 요청]  [여기로 오기]
```

자유 입력 채팅 없이도 협동이 되게 한다 (INV-10): 핑("여기·도움·준비·따라와·위험") · 역할 아이콘(지도·공구·드론·에너지) · 팀원이 멀어지면 월드 안 방향 표시 · 동시 스위치 준비 상태 · 팀 공유 진행 바 · 부활·구조 요청 버튼 · 자동 번역되는 사전정의 문구.

피할 것: 작은 채팅창만으로 협동 강요 · NPC 대사를 여러 명이 동시에 보며 진행이 꼬임 · 누가 무엇을 할지 안 보이는 미션 · 한 명만 정답 입력하고 나머지는 구경 · 음성 채팅이 없으면 깨지는 퍼즐.

## 5. 피드백 — 행동 뒤 1초 안에

| 상황 | 나쁜 피드백 | 좋은 피드백 |
|---|---|---|
| 경사 선택 오류 | "틀렸습니다" | 열차가 너무 낮은 플랫폼에 도착 + "높이 변화가 부족해" |
| 좌표 오류 | 빨간 X | 드론이 다른 구역으로 가고 목적지까지 거리·방향 표시 |
| 팀원 대기 | 반응 없음 | "Alex 가 신호를 기다리고 있어요" + 준비 아이콘 |
| 보상 획득 | 코인 숫자만 증가 | 도시 조명이 켜짐 + 새 이동 능력 즉시 사용 |
| 네트워크 지연 | 버튼 무반응 | 로딩 상태·재시도 표시·중복 클릭 방지 |
| 잠긴 지역 | "잠김" | 필요한 자격 배지와 다음 행동 표시 |

Roblox UI/UX 가이드의 원칙: 우선순위 · 주의 유도 · 시각 언어 · 관습 · 일관성. 배치에 따른 참여도 차이는 Experiments 로 검증 [미대조].

## 6. 접근성 — 기본 기능

자막 켜기/끄기 · 효과음·음악·진동 개별 조절 · 색각 이상 대응 패턴·아이콘 병행 · 충분한 대비 · 배경 투명도 감소 옵션 · 카메라 흔들림 감소 · 자동 이동/길찾기 보조 · 시간 제한 완화 모드 · 혼자 플레이 보조 NPC · 읽기 부담이 큰 플레이어를 위한 음성/아이콘 안내.

## 7. 디자인 토큰 제안 — "Neo Seoul × 수학마을" [자료 주장, 미결정]

- 톤: 따뜻한 미래도시 + 탐험 + 협동
- 색: 청록 = 길·안전·탐험 · 노랑 = 상호작용·보상·주의 · 보라 = 특별 미션·시민권 · 빨강 = 실패가 아니라 "재조정 필요"
- 형태: 둥근 카드 + 단청에서 영감받은 모서리. 복잡한 전통 문양은 버튼 안에 넣지 않는다
- 아이콘: 지도 · 열차 · 드론 · 패턴 · 한강 파도 · 게이트 · 자격 배지
- 피드백: 성공 = 도시 조명·음악·파티클 · 재도전 = 부드러운 방향 수정·힌트·즉시 재시작
- 색의 뜻은 모든 화면에서 같게 유지한다 (청록이 "경로"면 지도·목표선·카드·핑에서도 경로).

## 8. 자동 검수 체크리스트 (Q3 UI Harness 후보 — U1~U14)

| ID | 검사 |
|---|---|
| U1 | 360px 폭 작은 화면에서 필수 버튼이 모두 보인다 |
| U2 | 기본 조이스틱·점프 버튼과 커스텀 UI 가 겹치지 않는다 |
| U3 | 노치·홈 인디케이터·안전영역에 글자가 가리지 않는다 |
| U4 | 세로·가로 모드에서 핵심 미션 UI 가 유지된다 |
| U5 | 한 화면에 주 행동 버튼이 1개로 분명하다 |
| U6 | 터치·키보드·게임패드로 핵심 미션을 끝낼 수 있다 |
| U7 | 긴 번역문에서도 버튼·카드·대화창이 깨지지 않는다 |
| U8 | 색을 안 봐도 정답·위험·팀 역할을 알 수 있다 |
| U9 | 게임패드 포커스 순서가 논리적이다 |
| U10 | 자막·대비·투명도 설정이 적용된다 |
| U11 | 첫 60초 안에 첫 목표·첫 상호작용·첫 보상이 생긴다 |
| U12 | 실패 뒤 5초 안에 재도전 또는 힌트 행동이 가능하다 |
| U13 | 친구 없이도 핵심 온보딩을 통과한다 |
| U14 | 팀원 상태·준비 조건·다음 행동이 보인다 |

자료 결론: UI/UX 는 꾸미기가 아니라 아이의 시선을 월드와 친구에게 두고 학습 판단을 행동 속에 묻는 설계다. 수학마을 게이트에서는 버튼이 많은 것이 아니라 "빛나는 바닥 타일을 따라가고, 친구와 신호를 맞추고, 게이트가 열리는 결과를 본다"가 자연스러워야 한다.
