# RB Inspection Evolution

## 승인된 방향
사용자 결정(2026-10-06): 거대한 기하학 월드 대신 작은 공항형 심사대에 집중한다. 평소에는 플레이어가 NPC를 심사하고, 승급 때는 플레이어가 심사받는다. 다양한 수학 주제의 주장·증거·페이크와 판정 결과 연출을 활용해 자격 및 가상 시민 성장으로 연결한다.
이 결정은 방향 승인이다. 흥행, 학습효과, 지속 저장, 결제, 공개 출시 승인으로 확대 해석하지 않는다.

현재 필요한 Intent를 첫 문장에 명시한다:
“심사대 하나에서 근거를 얻어 판정하고 자발적으로 다음 사건에 참여하게 한다.”

## 먼저 읽고 재사용하기
저장소의 CLAUDE.md/AGENTS.md, intent.md, decisions.md, graph.json과 현재 관련 검증 상태를 읽는다.
설계 근거는 docs/knowledge/K2-arrival-gate.md와 docs/00-도시언어 게이트 통과 게임.md다.
구현을 볼 때 world/src/server/MissionService.luau, WorldView.luau, RewardService.luau, Analytics.luau 및 world/src/shared/Missions.luau, Text.luau와 client/Hud.client.luau를 우선 확인한다.
설계의 대화 예시를 구현 완료로 간주하지 않는다. 연결되지 않은 배지 ID도 보상 구현 완료가 아니다.
구체적인 참여 루프·첫 사건·측정·완료 조건은 references/participation-loop.md를 읽는다.

## 최소 작업 방식
1. 현재 Git HEAD·변경 파일·관련 Studio 상태를 읽는다. 다른 작업의 미커밋 변경을 덮어쓰거나 되돌리지 않는다.
2. 최신 사람 결정과 기존 정의를 대조한다. 기존 INV-8/11/15/16, DEC-10/12와 관계를 구체적으로 적는다. 현실 출입국 재현 제한이나 생성형 대화 제한을 플랫폼 정책으로 단정하지 않는다.
3. 구현 요청이 있을 때만 기존 Intent/결정/명세의 관련 부분에 최신 방향을 반영한다. 고정 ID와 기존 검증 연결을 보존하고 변경으로 실제 낡은 기록만 재검증한다. 충돌을 숨기거나 기존 통과 기록을 새 동작의 근거로 재사용하지 않는다.
4. 공통 심사대·판정·결과 연출을 재사용한다. MissionService는 좌표/기울기 행동에 직접 연결돼 있으므로 설정 변경만으로 완성된다고 주장하지 않는다. 필요한 작은 확장 하나를 선택한다.
5. 활성 병목 하나만 선택한다. 첫 병목은 “한 사건에서 질문 → 새 증거 → 근거 선택 → 판정 → 결과가 실제로 이어지는가”다. 초기 범위는 심사대 1개·좌표 주제 1개·사건 3개다.
6. 기존 Graph에 해당 작은 작업을 연결하고 기존 Harness와 evidence.jsonl을 사용한다. 새 위키·등록소·에이전트·게이트·원장·HTML 관리 시스템을 만들지 않는다. 원 evolution의 MathKing scaffold 생성 스크립트도 여기서는 실행하지 않는다.
7. 요청이 설계·전달뿐이면 스킬과 실행 지점만 전달한다. 구현·게시·배포를 했다고 말하지 않는다.

## 게임 설계 규칙
- 일상 역할은 심사관이다. 승급 심사는 같은 자료와 확인 도구를 이용해 플레이어가 신청자가 되는 특별 사건이다.
- NPC의 주장, 자료, 질문 응답으로 근거를 얻는다. 긴 대사를 읽기만 하거나 무작위 승인/추방을 누르는 것을 핵심 행동으로 만들지 않는다.
- 승인·추가 확인·페이크 반려/추방은 NPC 사건의 판정이다. 수학을 모르는 플레이어를 추방하거나 학습 진행을 영구 차단하지 않는다.
- “정보 부족”과 “거짓”을 구분한다. 충분한 근거 없는 신청자는 추가 확인 대상이다.
- 페이크는 수학적 모순·조건 누락에 둔다. 질문·자료·작은 확인 실험으로 구분할 수 있는 단서를 반드시 제공한다. 더 멋진 말투를 쓴다고 참이 되지 않는다.
- 상황과 행동 뒤에 수학 이름을 붙인다. 한 사건의 새 용어는 하나다. 일상어 표현 경로를 유지한다.
- 질문은 미리 작성한 짧은 분기로 시작한다. 개발 시 AI로 초안과 변주를 만들되 수학 검수를 거친다. 실시간 LLM·자유 입력·유저 간 심사 경쟁은 별도 요구 없이 추가하지 않는다.
- 판정 직후 도장, NPC 반응, 차단문, 자료 비교 등으로 원인과 결과를 보인다. 긴 연출로 다음 행동을 막지 않는다.
- 수학마을과 수학 교실의 취지를 유지한다. 가상 시민권은 세계 안의 명예/참여 자격이다.
- 심사대 복제는 공간 대량 생성이 아니라 같은 상호작용에 사건 팩을 교체하는 것이다. 다른 주제는 첫 루프 검증 후 하나씩 연결한다.
- 장기 진행 저장은 현 DEC-12 “저장 없음”과 구별한다. 첫 프로토타입은 세션 진행을 사용하고 지속 저장 완료라고 말하지 않는다.
- 첫 루프를 결제로 막지 않는다. 수익화 단계에서는 기존 공정 수익화 원칙을 지키며 선택적 외형/도장/심사대 장식부터 검토한다.

## 실제 참여와 제품 진화의 두 폐회로
플레이어: 사건 → 질문/확인 → 근거 기반 판정 → 결과 → 세션 경험/자격 진행 → 다음 사건 선택 → 승급 시 신청자 역할 → 새 확인 도구/사건 → 반복.
운영: 실행 관찰 → 끊긴 연결 하나 식별 → 사람의 짧은 관찰/교정 → 사건 또는 UI 한 부분 개선 → 같은 연결 재측정 → 유지/원복.
사건을 더 만드는 것은 진전이 아니다. 자발적 재참여와 수학 표현의 다른 맥락 재사용이 진전의 근거다.

## 검증·비용·보고
CODE_COMPLETE(코드와 관련 검사), BEHAVIOR_VERIFIED(Studio에서 전체 행동), REALITY_VERIFIED(목표 이용자의 실제 참여)를 구분한다.
외부 입력·판정·보상은 기존 서버 검증과 중복 지급 방지 경로를 사용한다. NPC 논리 시험, 전체 한 사건 Play, 모바일 질문/판정 조작에 필요한 검사만 추가한다.
Analytics 이벤트는 기존 허용목록을 확인하고 최소 필드만 확장한다. 대화 전문·자유서술·개인정보를 새로 수집하지 않는다.
샘플 수·분모·관찰 기간과 구현된 역할을 보고한다. 소수 테스트를 흥행 확정, 강제 진행을 자발적 선택, 세션 경험을 D1 유지율로 포장하지 않는다.
출시/대규모 광고 전에는 Roblox 공식 최신 정책·수익화 요건을 다시 확인한다. 정책 추측으로 새 검증 체계를 증식시키지 않는다.
첫 테스트는 재미와 행동 연결, 이후는 재방문·실제 결제·비용 차감 기여이익을 본다. 수익 재투자는 가장 큰 참여 이탈 하나 개선에 먼저 사용한다.
구조 재사용이 불명확하거나 핵심 근거가 모순되면 추가 구현을 멈추고 사실·미해결 쟁점·다음 지점을 보존한다. 사용자의 모델 승격 규칙에 따라 High 유지/매우 높음/Pro 중 하나를 이유와 함께 권고한다. 모델을 자동 변경했다고 말하지 않는다.
